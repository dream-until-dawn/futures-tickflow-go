## 文档结构与事实来源

主入口为可离线打开、按交易所/品种/状态筛选的HTML总览，另生成同源JSON和按交易所分组的Markdown表。六交易所分别列出；中金所金融期货与商品/航运指数类别明确区分。品种名称优先从已有受信供应商目录原件抽取，仅作显示，不冒充官方挂牌/规则证据；未知名称显示代码，不能猜造。

主表逐品种显示候选数、非空/空/本路线未请求数量、实际日线首末日与行数、参考来源与对照范围、待核字段/参考缺日、日历范围及未知行数、结算与成交额缺口和准入状态。未请求不写成无数据；没有参考的零差异不显示为对账通过；日期跨度不等于逐日完整；现有日历不等于价格/全生命周期获证。历史观察、当期供应商样本和日线主目录分层，不重复加总，尤其DCE/GFEX的旧样本不能被主目录零行掩盖。

生成器从已封存catalog、原报告、现有11份日历及冻结的补充样本元数据生成；校可信摘要、集合、计数勾稽和限制标志。HTML数据内嵌，不联网、无CDN，搜索/排序/详情只作用于元数据，不带原价CSV。正反向测试覆盖遗漏品种、篡改计数、未请求冒充覆盖、无参考冒充一致及补充样本重复计入。

## 已落地文档及维护方法

主入口为[数据情况总览](data-status.html)，同源产物为[完整Markdown表](data-status.md)和[JSON模型](data-status.json)。覆盖冻结供应商候选中的六交易所89品种（商品/航运81、金融8），不是官方市场全集。主目录与其他路线分栏；新浪234份非空当期样本、EDB旧三份334行样本只作补充，不加进主目录377305行。样本数与异常基于冻结元数据，本轮不重新核其原CSV。

已有11份制度日历按品种及真实日期显示；缺范围继续未知，不套当前模板。主EDB缺结算/成交额列与参考原表已有列分开，列存在也不表示每行有值、单位已核或已经可供统一Source消费。没有日历或参考时不渲染为通过状态；当前取样比和观察跨度均不称完整率。其他既有资料包的准入范围不由本页改变。

生成源码位于 `tools/research/status/`：`sources.json`锁资料身份，`labels.json`只维护阅读别名；`extract_names.py`从已封存完整目录流式提取名称，保留51项旧身份冲突隔离，三位源代码不改变合约年份。`page_model.py`汇总与校界，`generate.py`产生三份文档，`assets/`保存页面/样式/交互，`browser_check.cjs`做本地浏览器验收。

资料变化时按以下顺序维护，不覆盖旧封存：

1. 先取得并验证新的合法输入包/报告；受阻入口不能借刷新文档重试。更新`sources.json`中的明确来源、摘要和资料日期；若目录名称变化，再从受信原件生成新名称元数据，不能凭猜测填官方事实。
2. 运行 `python -B -X utf8 tools/research/status/generate.py --bundle <受信研究包> --out-root <全新仓外目录>`。它只读旧包与锁定元数据，不联网、不改原件。输出在输入包内部或已经存在会拒绝。
3. 检查来源、每品种统计及限制后，把三份产物复制到`docs/`；将新`data-status.json`的SHA256写入`sources.json`的`published_model_sha256`。不要只手改HTML或Markdown掩盖数据变化。
4. 用 `python -B -X utf8 tools/research/status/generate.py --check-docs`核公开模型和文档的逐字节再生；该模式不需要仓外原价包，已纳入Python枚举测试。它验证公开模型/来源锁与渲染，不冒称在CI重新读取全部原CSV。
5. 运行状态目录正反测试及本机浏览器检查，保留全模块/CI和相应迁移证据再合并。浏览器只打开本地HTML，无CDN或网络请求；桌面表格、移动端卡片、搜索/筛选/详情和空结果均有检查。

本轮已实际用四个有效源码副本移除空响应覆盖、全局计数勾稽、补充元数据SHA及手改HTML漂移守卫；每个副本均命中目标`ValueError not raised`断言失败，而非被无关失败挡住。见[破坏实验](evidence/data-status-20261115/source-mutations.json)。产品名解析和零状态计数的实际缺陷已修正并保留反向测试，没有用旧错误结果覆盖当前文档。
