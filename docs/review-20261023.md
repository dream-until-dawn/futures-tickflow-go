## 发现与处理方案

1. 预检的 --env-file 可以指向任意文件，而生成的 Go 测试命令只读取环境变量或根目录 .env，二者凭证来源不一致。保留参数但拒绝非仓库 .env 的路径，在输出 PASS 或命令前失败；不把凭证值打印到命令中。新增测试先复现错误，再修复，并验证环境变量优先及缺凭证时不生成命令。
2. 原预检只手工验证了有效窗口，没有自动测试时间过期路径。为 main 增加可注入的 argv 与当前时刻，默认行为不变；测试窗口开始前可生成命令、开始之后失败，10/23 不输出过期的 9/30 或 10/8 执行命令。注入只供测试调用，命令行不提供伪造当前时间的选项。
3. adapter 的有限数失败只断言 Start 为零，其它字段没有验证零结果；补全零结果断言。此为测试覆盖补强，不改变 API。
4. 原断线工具使用固定 20260921、20260922 日历，并且关闭后立即重连。不能只改环境变量就宣称测试了“超过 30 根的断线”。新方案先落文，工具改造及其离线标定另行实施；本批不修改生产 Live 的重连机制。

## 当前评审范围

adapter.Bar 按规范合约字段映射，逐个拒绝 High/Low/Close 的 NaN/Inf 后才调用 decimal.NewFromFloat；时间使用毫秒与固定东八区，TradingDay 不从自然日推算。对方业务守卫保留在 Advance。固定依赖为 F9b 合并版本，不使用本机模拟器 replace。主连的 RawClose 不足以恢复 High/Low，日线及跨休市聚合根不适合直接作为 Advance 的盘中输入，边界已在 adapter/README.md 中披露。

集成测试的账户是空仓，仅支持“接口与时段拒绝路径已验”的结论；没有证明真实持仓计价或撮合闭环。不将旧的全绿记录当作本次验证结果。
