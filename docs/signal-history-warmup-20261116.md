# 既有官方历史结算的离线预热补充

接续main 353825b。目标是将已有官方历史结算整理为指标预热输入，继续保持用户两道数据门槛；不增加网络请求、不重试受阻入口、不部署生产、不打tag。旧单日包和消费结果原样保留。

## 可行性与范围

已独立重读685574条官方目录记录并核SHA；当前527个信号适用约中503有目标日前历史。初探每约64个观察日得到28344条历史、128份原件/10316754字节；51品种至少35日、SO仅3日。这个探针只证明数据可取，**不证明当前指标可预热**，原探针[保留](signal-history-warmup-20261116-probe.json)。

随后独立核对本仓indicator/internal.go、macd.go及引擎固定版本column/formula_test.go：现行CN MACD(12,26,9)收敛606根，含前值条件列实际第607根才可ready。因而在实现前将计划改为**当前具体合约全部已有可溯源结算**，不人为截64，也不换算法或拼主连。[完整探针](signal-history-warmup-20261116-full-probe.json)得到63670条历史，457份原件/146420884字节全部SHA一致；只有INE.sc的最长当前合约sc2612达715观察日，有可能满足该默认模型，其余如实保留不足。此为数据长度判断，实际策略结果须再验。

郑商所历史三位码只与同日XML显式年份/月份、首次及最后交易日期共同绑定；缺首次日期或不在所列生命区间的历史不纳入，不按临近年份猜测。原目标日16日及信号交易日17日保持；新月份仅有目标日单条时不补造过去。

## 分期和边界

先按[冻结计划](research-plans/signal-history-warmup-20261116.json)实现离线选择、原件/回执校验和新包生成，再做正反测试与消费者实测。源版本结算冲突即停止；缺失或非正历史结算不补值并计数。原件、目录、解析清单均按摘要绑定；文件数及总原件字节预算固定。输出必须新目录，失败不能覆盖旧包。

沿用user-data-gates-v1。新包仍是pure signal，current_contracts为空、回测pending；历史部分只交付settle，其余字段为null代表本包未交付，不声称原表没有这些值。目标日原字段照留。保留2021起且能明确绑定当前合约的全部已有观察，不以此认证日历连续无缺日，也不虚造结算、主连或历史制度。需年度解码的资料同时附原始归档、已核解码产物和解码器身份，不把派生产物叫原始响应。

实际就绪数量必须由引擎读入真实包后测得；指标窗口不足不改变已有数据门槛。逐行源身份和目标日结算仍须独立核；源响应最初HTTP接收时间未知时不把旧留存事件或本次打包时间冒充采集时刻。
