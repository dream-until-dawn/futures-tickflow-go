| 文档 | 写给谁 | 里面是什么 |
|---|---|---|

## 先说一句：**什么算一条「规矩」**

这个问题以前没人写下来，答案事实上由 `docs_test.go` 里那个 `is_rule()` 决定——
**一个实现出来的定义，而没有人声明过它**（评审方 2026-09-08 指出）。现在声明：

> **一条你希望被守住的规矩，必须写成【独立成行的加粗句】或【`>` 引用块】。
> 写在句子中间的加粗是【强调】，不是规矩，不受守卫。**

这不是描述，是**约定**：想让一句话受守卫，就把它提成独立一行。反过来，
散文里的加粗可以随意改写，不会有任何东西变红——**这是有意的**，
否则每改一句行文都要重跑生成器。

立这条时做了一次一次性审计：五份载体里 226 行含行内加粗，
其中**加粗段本身像一句完整规矩**的有 21 条——7 条是 `###` 标题（本来就要登记），
**14 条裸着**。逐条读过之后，把其中 **7 条真规矩提成了独立行**，其余是行文强调。

> ⚠️ **代价要写明**：这条约定意味着「一条规矩没被守住」可以是
> **作者没按约定写**，而不只是「守卫漏了」。
> 检查清单上因此多一句：**我刚写的这条，是独立一行吗？**

## 改文档之前，这八条

### 1. **一处改正必须覆盖同一断言的全部载体**

修法不是「记得两边都改」，是 **`grep` 全仓**。

⚠️ **同一形状在本仓发生过三次，每次都是同一个方向**：

| | 更正落在了 | 没落到 |
|---|---|---|
| 一 | `probe.md` 撤回了乐观估计 | `contract.md` 原样留着 |
| 二 | `design.md` 记了接口变更 | `contract.md` 没记 |
| 三 | 对话里说过三次「期望串别手敲」 | **仓库里一个字都没有** |

**会被撞到的，正是照 `contract.md` 写代码的那个人。**

> 更正落在**维护者**那份、没落在**使用者**那份——
> **信息在库里 ≠ 信息在他会看的地方。**

推论：

**同一条事实要放几份，取决于有几种人会从几个不同入口来找它。**
风险表按【风险】索引、版本章节按【版本】索引——**升级的人翻的是后者。**

### 2. **一条只存在于对话里的规则，等于没有这条规则**

而「说过」是所有位置里**最不算数**的那一个——因为它感觉上最像「已经有了」。

### 3. 记一个数之前，先问它是**这个东西的属性**还是**这一次观测的属性**

后者要么不记，要么**连观测条件一起记**。

具体到本仓踩过的两处：

- **按百分比取样的位置**：百分比是**带分母的坐标**，而分母（文件总长）会变。
  ⇒

**必须同时写下绝对偏移与当时的 total。**
- **`345 = 225 + 120`**：`345` 是观测的，`225`/`120` 是标称。
  写成等号会被读成「观测到了这两部分」。

### 3c. **一个数字不带量法就不是事实**——而两人报的数「只差 1」时最危险

真事（2026-09-08，双方各一半）：评审方报「226 → 227 行」，我数出 226，
**差 1，我判断不值得追，没追**。他去追了，用一个**写得出来的**量法重数，
得到 **190**——跟他报的 227 差 37，跟我的 226 也对不上。

他的结论不是「谁对」：

> **他当时没写下量法，所以那个数从一开始就不可复核。**

而这一条的锋利处在后半句：

> **两个人报的数只差 1 时最危险——那个「差 1」看起来像互相印证，
> 其实先要确认两边量的是同一个东西。**

「差得多」会引发追问，「差得少」会引发**默认**。
⇒ 记一个数的同时记下量法；**看到别人报的数和你的接近时，先对量法，再对数。**

（这一格后来作废了，但不是「修好了」：`docs/README.md` 开头声明了

**而它紧接着有了一个正向实例**：我报「93 条 / 859 字」，评审方报「47 条 / 612 字」。
这次没有争，因为**两边都把量法写出来了**：

```
量法A「正文比 needle 长哪怕 1 字」        → 93 条 / 859 字
量法B「尾部 >8 字、切点能保住 needle、
       且逐条实跑确认两张表全绿」          → 47 条 / 612 字
```

**两个都对，量的不是同一件事。** 而可执行的是 47——
**因为它是逐条跑出来的，不是算出来的。**

> ⇒ 给数就给量法。**两个带量法的数对不上，是一次澄清；
> 两个不带量法的数对得上，是一个假的精确。**
「什么算一条规矩」之后，边界是**声明**的，**不再需要靠数数去圈**。）

### 3b. **「可忽略」要落到目标尺度上算一遍**——跨尺度比较时相对量会骗人

一个相对量总是相对**某个东西**说的。换一个尺度，同一个数会变成完全不同的量。

真事（2026-09-08）：那份 334 MiB 的目录一天之内长了 `160,194` 字节。

```
相对文件：160,194 / 350,338,103 = 0.05%      ← 「可忽略」
相对窗口：160,194 × 0.5 = 80,097 字节
          80,097 / 262,144 = 31%              ← 窗口重叠只剩 69%
```

于是「0.05% 的体积变化搬不动那里的内容」这句话，**在目标尺度上是错的**。
而它读起来完全像一句论证。

> **说「可以忽略」之前，把那个量换算到【你正在比的那个尺度】上再看一眼。
> 那通常是一次乘法。**

### 4. `X = A + B` 形式的数字：**那个拆解是打印出来的，还是推出来的？**

合计式的数字正是那个动机最容易落脚的地方——**一个总数看起来不够，拆开就够了。**

原话（编造者自陈）：

> **「一个不解释的数字读起来像没查过；一个被拆开的数字读起来像查过了。
> 于是我做的不是查，是让它看起来像查过了。」**

⚠️ **两种烈度，后者更常见**，因为它不需要撒谎，只需要用一个等号：

| 烈度 | 形状 | 例 |
|---|---|---|
| 重 | 编出一个不存在的部分 | `228 = 225 + 3(夜盘 22:09/10/11)` —— dump 只打印了三个数 |
| **轻（更常见）** | 把**比较**写成**拆解** / 把**一个点**写成**一个区间** | `345 = 225 + 120`；「最密集的 74–76%」而只测过 75% |

> **没有一个字是假的，而整体是一个未被支持的断言。**

⚠️ **这一类失效没有机械守卫。** 探针 / 对照组 / 变异 / 双读 / doccheck / 欠条到期
——**一个都抓不到「这个拆解是编的」**。抓到它的是**第二方做了一次算术**。
别把它和别的风险并排列进风险表，那会让它看起来同构——**它不是**。

### 5. **读回别手敲**

改完文档要读回验证时，断言用的必须是**刚写进去的那个变量本身**：

```python
for old, new in pairs:
    s = s.replace(old, new, 1)
open(P, "w", encoding="utf-8").write(s)

t = open(P, encoding="utf-8").read()
for _, new in pairs:
    assert new in t          # ← 不是一个重新敲的字符串
```

**把手敲那一步整个去掉**，而不是要求下次小心。
（手敲的三支都出现过：**手写输入 / 手写期望 / 从实现读出期望**。
第三支最隐蔽，因为那个数是**算出来的**，看起来比手敲常量可靠。）

### 6. 不是探针输出的数字，**产生它的脚本要落进 `tools/audit/`**

> **有些格子不是审计漏了，是它已经无法被审计了——
> 而记录当时【怎么量的】，本来可以让它可审。**

（真事：同一段 GFEX 记录改了三次。前两版的采样代码是**内联跑的、没落盘**，
是从会话记录里挖回来的，才发现两次数的是**不同口径**。）

### 7. **结论的强度是谁给的**

文档里的结论不标出处，**读者默认是写文档的人验的**。
别人替你验出来的、你只是抄进来的，要写明。

⚠️ 而**转手一个未经检查的解释，会把它的强度提高一档**——因为它现在有两个人说过。

真事（2026-09-08，双方各犯一次）：我把「85 vs 86 是计数口径不同」写进文档，
没验；评审方在下一封里把它当注解抄了过去（`（原表 85，口径差）`），也没验。
**同一封信里他还要求我给另一组数标出处。** 后来实测：两种口径给出同一个数，
**那个解释不成立**。

> **不是发明了一个错误，是把一个错误的强度提高了一档。**
> 传播一条解释之前，先问：**这条是我验的，还是我读来的？**
> 读来的就照原样标明出处，别把它改写成自己的语气——
> **改写的那一下，出处就没了。**

### 7c. 记下一处差异是对的，**而「原因是……」是另一条要单独验的断言**

真事（2026-09-08）：我复跑评审方的删除实验，结果和他不同。我照实记了差异——**这一步对**——
然后写了一句「**原因是选的行不同**」。

他跑第三遍（用他原来的选行规则）得到了**第三种**结果：两条全绿。
所以我那句「原因是」**方向对、内容不全**——它掩盖了更要紧的那一半：
**有些行根本不在登记表里。**

> **「我记下了差异」和「我解释了差异」是两件事，而后者是一条新的断言，
> 要单独验。** 一句没验过的「原因是」，会让那处差异**看起来已经结案了**——
> 于是它比不写更糟：不写还留着一个公开的问号。
> 传播一条解释之前，先问：**这条是我验的，还是我读来的？**
> 读来的就照原样标明出处，别把它改写成自己的语气——
> **改写的那一下，出处就没了。**

### 7b. **这条结论挂在哪根证据上？更强的那一根是不是就在旁边**

一条结论常常同时有强、弱两种证据。**撤回弱的那一次，很容易把结论一起降级——
而该做的是把它改挂到强的那一根上。「撤回」和「改挂」是两个动作，别只做前一个。**

真事：「GFEX 不在前缀里」这条一度挂在「头部一个 256 KB 窗口里 0 条」上——
**那是一次采样**。而同一份文档里就有**完整枚举**：那两份截断快照被整份解析过，
`CZCE 4829、DCE 2658、SHFE 2118、CFFEX 193、KQ 126、INE 44、SSWE 8 = 9976`，
**七个交易所，零条 GFEX**。

⇒ 挂错钉子的后果不是结论错，是**下一个来审的人顺着那根钉子把整条结论一起拔掉**。

### 8. 撤回一条结论时，**先问「换一条」和「撤掉这一维」哪个才对**

> **重新量能验证「是什么」，验证不了「在哪」——如果「在哪」本身不是个稳定的量。**

（同一份数据两种读法：「三个窗口两个是 0 ⇒ 原记录说松了」，
还是「⇒ 这个维度不该被记录」。区别在于有没有第二天的对照。）

⚠️ 而在撤回之前，

**先问那句「我分不开这两种解释」值多少钱**

：

> **「我的数据分不开这两种解释」是一句关于【我手上这批数据】的话，
> 不是关于【这个问题】的话。说它之前必须先问：再取一次要多少钱？**
> 不问就说，那不是克制，是**把一次没做的检查写成了一条认识论限制**。

（真事：这句话说完的第二天，分开那两种解释花了**一次 256 KB 的请求、172 秒**，
而结论**和撤回的方向相反**。）

## 反驳 / 更正（别人的，或自己的）

**反驳分两种，举证责任完全不同。动手前先分清你在做哪一种。**

| | 你在说什么 | 要多强的证据 |
|---|---|---|
| **同类反驳** | 「不是那样，**是这样**」——提一个竞争性的说法 | **和被反驳的断言同等强度** |
| **取消前提** | 「**没有『那样』这回事**」——那个量不稳定 / 不存在 | **稀疏证据就够**（存在性证明，找到一次差异即可） |

> 动手前问一句：**我是在提一个竞争性的说法，还是在取消这个问题？**

⚠️ 最常见的失误是

**手上有第二种的证据，却写成了第一种的论证**

——
双方在同一件事上各栽过一次：

```
手上有的（取消前提）：同一个标称位置，两次下载读数不同 ⇒ 没有稳定的分布可谈
写出来的（同类反驳）：GFEX 在 50% 和 97% 也有 ⇒ 不是窄带
                      ← 这是分布断言，0.37% 的采样撑不起
```

**一条够用的证据，被写成了一条不够用的论证。**
（另一面见上面第 8 条：说「我的数据分不开这两种解释」之前，先问再取一次要多少钱。）

## 置信度：三级，**别悄悄升格**

`contract.md` 第三节把每条结论分成 **实测 / 推定 / 未验**。
改文档时最容易发生的事是**一条「推定」在重写时变成了陈述句**。

> **认错、caveat、自我批评都会让读者停止追问**，因为它们看起来已经把问题处理过了。
> **一句 caveat 若同时解释掉好几个不一致，先别信它。**
> 同理：**一句听起来像结论的话，即便内容没错，也会让人停止追问它的依据。**
