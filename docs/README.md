|---|---|---|

## 改文档之前，这八条

### 1. **一处改正必须覆盖同一断言的全部载体**

修法不是「记得两边都改」，是 **`grep` 全仓**。

⚠️ **同一形状在本仓发生过三次，每次都是同一个方向**：

| | 更正落在了 | 没落到 |
|---|---|---|
| 一 | `probe.md` 撤回了乐观估计 | `contract.md` 原样留着 |
| 二 | `design.md` 记了接口变更 | `contract.md` 没记 |
| 三 | 对话里说过三次「期望串别手敲」 | **仓库里一个字都没有** |

**会被撞到的，正是照 `contract.md` 写代码的那个人。**

> 更正落在**维护者**那份、没落在**使用者**那份——
> **信息在库里 ≠ 信息在他会看的地方。**

推论：**同一条事实要放几份，取决于有几种人会从几个不同入口来找它。**
风险表按【风险】索引、版本章节按【版本】索引——**升级的人翻的是后者。**

### 2. **一条只存在于对话里的规则，等于没有这条规则**

而「说过」是所有位置里**最不算数**的那一个——因为它感觉上最像「已经有了」。

### 3. 记一个数之前，先问它是**这个东西的属性**还是**这一次观测的属性**

后者要么不记，要么**连观测条件一起记**。

具体到本仓踩过的两处：

- **按百分比取样的位置**：百分比是**带分母的坐标**，而分母（文件总长）会变。
  ⇒ **必须同时写下绝对偏移与当时的 total。**
- **`345 = 225 + 120`**：`345` 是观测的，`225`/`120` 是标称。
  写成等号会被读成「观测到了这两部分」。

### 4. `X = A + B` 形式的数字：**那个拆解是打印出来的，还是推出来的？**

合计式的数字正是那个动机最容易落脚的地方——**一个总数看起来不够，拆开就够了。**

原话（编造者自陈）：

> **「一个不解释的数字读起来像没查过；一个被拆开的数字读起来像查过了。
> 于是我做的不是查，是让它看起来像查过了。」**

⚠️ **两种烈度，后者更常见**，因为它不需要撒谎，只需要用一个等号：

| 烈度 | 形状 | 例 |
|---|---|---|
| 重 | 编出一个不存在的部分 | `228 = 225 + 3(夜盘 22:09/10/11)` —— dump 只打印了三个数 |
| **轻（更常见）** | 把**比较**写成**拆解** / 把**一个点**写成**一个区间** | `345 = 225 + 120`；「最密集的 74–76%」而只测过 75% |

> **没有一个字是假的，而整体是一个未被支持的断言。**

⚠️ **这一类失效没有机械守卫。** 探针 / 对照组 / 变异 / 双读 / doccheck / 欠条到期
——**一个都抓不到「这个拆解是编的」**。抓到它的是**第二方做了一次算术**。
别把它和别的风险并排列进风险表，那会让它看起来同构——**它不是**。

### 5. **读回别手敲**

改完文档要读回验证时，断言用的必须是**刚写进去的那个变量本身**：

```python
for old, new in pairs:
    s = s.replace(old, new, 1)
open(P, "w", encoding="utf-8").write(s)

t = open(P, encoding="utf-8").read()
for _, new in pairs:
    assert new in t          # ← 不是一个重新敲的字符串
```

**把手敲那一步整个去掉**，而不是要求下次小心。
（手敲的三支都出现过：**手写输入 / 手写期望 / 从实现读出期望**。
第三支最隐蔽，因为那个数是**算出来的**，看起来比手敲常量可靠。）

### 6. 不是探针输出的数字，**产生它的脚本要落进 `tools/audit/`**

> **有些格子不是审计漏了，是它已经无法被审计了——
> 而记录当时【怎么量的】，本来可以让它可审。**

（真事：同一段 GFEX 记录改了三次。前两版的采样代码是**内联跑的、没落盘**，
是从会话记录里挖回来的，才发现两次数的是**不同口径**。）

### 7. **结论的强度是谁给的**

文档里的结论不标出处，**读者默认是写文档的人验的**。
别人替你验出来的、你只是抄进来的，要写明。

### 8. 撤回一条结论时，**先问「换一条」和「撤掉这一维」哪个才对**

> **重新量能验证「是什么」，验证不了「在哪」——如果「在哪」本身不是个稳定的量。**

（同一份数据两种读法：「三个窗口两个是 0 ⇒ 原记录说松了」，
还是「⇒ 这个维度不该被记录」。区别在于有没有第二天的对照。）

⚠️ 而在撤回之前，**先问那句「我分不开这两种解释」值多少钱**：

> **「我的数据分不开这两种解释」是一句关于【我手上这批数据】的话，
> 不是关于【这个问题】的话。说它之前必须先问：再取一次要多少钱？**
> 不问就说，那不是克制，是**把一次没做的检查写成了一条认识论限制**。

（真事：这句话说完的第二天，分开那两种解释花了**一次 256 KB 的请求、172 秒**，
而结论**和撤回的方向相反**。）

## 置信度：三级，**别悄悄升格**

`contract.md` 第三节把每条结论分成 **实测 / 推定 / 未验**。
改文档时最容易发生的事是**一条「推定」在重写时变成了陈述句**。

> **认错、caveat、自我批评都会让读者停止追问**，因为它们看起来已经把问题处理过了。
> **一句 caveat 若同时解释掉好几个不一致，先别信它。**
> 同理：**一句听起来像结论的话，即便内容没错，也会让人停止追问它的依据。**
