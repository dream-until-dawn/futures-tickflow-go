# v0.8.0

## 这一版有什么

```
取法（读数求于 main 0742950；⚠️ 打 tag 前在 tag 尖上重跑一遍，差异逐条补进来）：
  对外变更只认【树比】 git diff v0.7.0 <本版>，不认按提交列
  导出声明：两个引用各 git archive 一份，非 tools/、非 _test.go 的每个包用 go/ast 收导出的函数/方法/类型/结构体字段/接口方法/常量/变量，
            签名按 go/printer 文本逐键比（一次性工具，不进仓；与 v0.6.0 / v0.7.0 那两次是同一支）
            ⚠️ 口径：导出接口的方法**不论方法本身导不导出都记一条**（结构体字段只记导出的）——
               未导出的接口方法让那个接口在包外实现不了，也是契约的一部分。v0.7.0 那次没有这种方法，那次的数不受影响
            标定两端：同一引用（0742950 → 0742950）比出 0 条；已知只多一格的一对（3e87aaf → 8738880）恰好报出 SyncReport.HeldBack 一条
            ⚠️ 射程：比不了常量的值、比不了行为 ⇒ 行为变更另从 diff 与测试里列
            读数：v0.7.0（9af79be）→ 0742950 新增 30 · 删除 0 · 签名变 0 · go.mod 未变
                  根包 10：type Indicator / Settler · Indicator 的 5 个接口方法 · Settler.Settle · func IndicatorSettle / IndicatorKeys
                  indicator 20 ＝ 19 个导出名 ＋ 1 条导出接口上的未导出方法 Option.apply（它让 Option 在包外实现不了）
                  根包原有声明：删除 0 · 签名变 0（上面全仓的 0 含根包）

  已有包：git diff v0.7.0 0742950 -- . ':!*_test.go' ':!docs' ':!indicator' ':!indicator_api.go' ':!tools' 为空
            标定：同一条筛子在 v0.5.0 → v0.6.0 上报 18 个文件 ⇒ 筛子不是恒空
```

### ✅ 新增的

```
一  根包 indicator_api.go：流式指标接口                                                      出处 0742950
    Indicator（Name · Fields · Warmup · Update(b Bar) · Reset）· Settler（Settle）· IndicatorSettle · IndicatorKeys
    自姊妹项目 okx-tickflow-go v1.4.2（a2d1c0b）移植，签名只差一处：Update 吃 Bar，不吃 Candle
    （用户 2026-09-17 定：自定义指标由此能读 Bar.OpenInterest；本版不内置持仓量指标）

二  indicator：内置七个指标 MA · EMA · MACD · KDJ · RSI · CCI · BOLL                           出处 0742950
    公式、两套口径的三处差异（递归平均的播种 · MACD 柱 ×2 · KDJ 的平滑）、BOLL 用总体标准差、平盘与边界的约定 —— 照搬姊妹仓，
    非注释的代码行与姊妹仓逐行相同（机械替换 Candle ⇒ Bar 之后 diff，筛子改一行即报出，已标定）
    Compute / ComputeField · Named · SetDefaultConvention / DefaultConvention
    ⛔ **默认口径 CN，是用户 2026-09-17 定的，不是量出来的**：照搬姊妹仓的配置。国内期货软件（文华 / 博易 / 快期）用哪套，
       本库没有读数；姊妹仓的 CN 是拿 OKX 平台逐行比出来的，对象是 OKX。问句与所选项逐字记在 docs/design.md §十五「v0.8 起手」零
    内置七个只读 High / Low / Close：Turnover / Settle / Volume / OpenInterest 全是 NaN 也不影响输出（测试逐位钉着）

三  Settle 的契约：「只预读 Settle() 根时，与从头喂到底只差几个 ULP」，不保证逐位相等                 出处 0742950
    ⚠️ 与姊妹仓的说法不同。姊妹仓的注释与测试把 Settle() 当作「逐位收敛点的上界」；本库在新浪 RB0 日线上量出它不成立：
       RSI14 两套口径的逐位稳定点 508 / 525，而 Settle() 是 482 / 469（docs/probe.md 6.34）。
       逐位稳定点跟着数据的数值与舍入走（同一段价格乘 100 就到 537），任何只由递推系数算出的数都封不住它。
    ⇒ Settle() 与 settleEps 没改（照搬）；测试断言「Settle() 处相对误差 ≤ 2e-15」（RB0 末 1000 根上实测最大 8.01e-16），
       逐位稳定点只印成读数。几个 ULP 对任何用途都无意义，按 Settle() 预热就够

四  期货特有的读数与测试（docs/probe.md 6.33 · 6.34，design.md §十五「v0.8 起手」二）
    甲  （rb 一个品种、新浪合约级日线 ≈2018 起、35 份已到期合约上实测）单个合约的日线上，EMA / RSI / MACD（两套口径）**值取决于从哪一根开始喂，不会收敛**：
        35 份已到期 rb 合约日线 236–243 根，34 份上逐位测不出收敛；RB2412 那一份是量法的退化格（前两根收盘相同），照判对记「垮」
        ⇒ 要收敛的值，喂主连（continuous）。写进了包注释、Settler 注释与 contract.md 静默风险表
    乙  「增量 == 批量」在合成的涨跌停锁板（30 根）与长假跳空上逐根逐路成立（容差照姊妹仓：相对 1e-9）
    丙  锁板段上不出 ±Inf，窗口整个落在锁板里时照平盘约定（CCI 0 · BOLL 三轨重合 · KDJ 趋向 50）
    丁  四个可能为 NaN 的字段不影响内置指标
    戊  「Settle() 在期货数据上仍然够用」—— **垮了**（新浪 RB0 日线末 1000 根上实测，见三）
    测试数据：indicator/testdata 下三份新浪日线原始响应（RB0 · RB2501 · RB2412，2026-09-17 取回的原样字节，md5 钉在测试里）
    测收敛点的量法与姊妹仓不同：量「从此一直逐位相等」的稳定点，不量「第一个逐位相等」（后者不单调、会低估），并识别「开头价格重复」的退化格
```
