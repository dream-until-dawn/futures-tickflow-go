# v0.7.0

## 这一版有什么

```
取法（读数求于 main a66a087；⚠️ 打 tag 前在 tag 尖上重跑一遍，差异逐条补进来）：
  对外变更只认【树比】 git diff v0.6.0 <本版>，不认按提交列
  导出声明：两个引用各 git archive 一份，非 tools/、非 _test.go 的每个包用 go/ast 收导出的函数/方法/类型/结构体字段/接口方法/常量/变量，
            签名按 go/printer 文本逐键比（一次性工具，不进仓；与 v0.6.0 那次是同一支）
            标定两端：同一引用（a66a087 → a66a087）比出 0 条；已知只多一格的一对（3e87aaf → 8738880）恰好报出 SyncReport.HeldBack 一条
            ⚠️ 射程：比不了常量的值、比不了行为 ⇒ 行为变更另从 diff 与测试里列
            读数：v0.6.0 → a66a087 新增 141（continuous 63 · calendar/derived 78）· 删除 0 · 签名变 0 · go.mod 未变
            ⇒ **公开 API 没有删除、没有签名变化**；新增的全部在两个新包里
  已有包：git diff v0.6.0 a66a087 -- . ':!*_test.go' ':!docs' ':!continuous' ':!calendar/derived' ':!tools' 为空
            标定：同一条筛子在 v0.5.0 → v0.6.0 上报 18 个文件 ⇒ 筛子不是恒空
            ⇒ **v0.6.0 已有的包，非测试源码一行没动** ⇒ 本版没有「编译照过、行为变了的」，也没有勘误
            这个「⇒」的依据另外三条（都量过）：
              go.mod / go.sum 在 v0.6.0..本版之间没有 diff ⇒ 依赖版本相同
              全仓 //go:embed 只有一处，在 docs_test.go（测试）⇒ docs 下的改动不会被嵌进库
              两个新包不被任何已有包 import（引用它们的只有 calendar/derived 自己与 tools/derivedreport）⇒ 它们的 init 碰不到已有包
  出处：main 上把它合进来的那颗合并提交

### ✅ 新增的

```
一  continuous：主力连续 —— 换月拼接 ＋ 复权 ＋ 交出接缝                                      出处 057a74b、9a3ba78、492c900、41cdb95、a66a087
    Build(ContinuousSpec, []DayBars) (Continuous, error)
      输入是【每天的候选合约与各自那一根】，由调用方从库里读好递进来 —— 本包不收提供者、不碰交易日历（两道包级守卫钉着）
      Continuous 交出：Bars（拼好、复权后的序列）· Rolls（每个接缝：换月日、旧→新、Basis、Factor、规则实际数到的那一段 Counted）·
                       Days（本次用的天轴 ＝ 库里有根的日子）· First 与 ContractAt(i)（第 i 根属于哪个合约）·
                       NoPick（规则说不清主力的那些天）· RewritesHistory（前复权的警告）
    换月规则四条：ByOpenInterest · ByVolume · ByOIAndVolume（两者都最大才认，否则那天记进 NoPick）·
                  FixedBarDaysBeforeExpiry(n)（数的是【库里有根的日子】，不是日历交易日；到期日未知 ⇒ 报错 ErrExpiryUnknown，不跳过候选）
    复权：RatioBack（零值，即默认）· DiffBack · RatioFwd · DiffFwd · NoAdjust
      ⇒ 默认比例后复权：历史一经生成不再变（可复现）。用户 2026-09-17 裁，问句与所选项逐字记在 docs/design.md §八
      ⇒ 前复权 ⇒ Continuous.RewritesHistory 非空：下一次换月之后，这条序列的全部历史价格都会变（不进错误，只留声）
      ⇒ 不复权要显式写 NoAdjust（＝ 新浪 RB0 的口径，换月日有 1.5–1.7pp 的假收益）
      ⇒ 不在这五个值里的 AdjustMethod ⇒ Build 报错
      复权只动价格，不动 Volume / OpenInterest
    报错：ErrDaysNotAscending（天不是严格升序，不自己排序）· ErrNoBarForPick · ErrRollPriceUnusable（换月价为 0 / NaN / Inf）· ErrExpiryUnknown

二  calendar/derived：从 1m 主连逐天判夜盘，与注入的日历比出差异                                出处 6e89937、aa52abc、163c3e3（守卫，只改测试文件）、827b01a、a8f24a5、d078de1
    ⛔ **它不产出日历，也不改日历**：交易日由调用方注入的日历裁（D-B），本包只把对不上的天报出来，处置交给人
    Judge(Input) (Report, error)：逐天给结论 a（夜盘有量）· b（有夜盘根而无量）· c（没有夜盘根）· 或带原因的「无结论」
      无结论的三种原因：尾部未登记（挂起或还没同步到）· 永久洞（库侧没拉过）· 规则没给出主力（NoPick）
      Report 印无结论的占比与分项 —— 占比每次都印，免得它悄悄蚕食判出的天
    Compare(Report, []BaseDay)：与摊平的 base 快照逐天比，六种差异（DiffKind）；base 比报告窗口宽 ⇒ 报错，不静默截
    三道「只读」守卫：签名层 · 调用层 · 导入白名单

三  tools/derivedreport：差异报告工具（derived 的显式调用入口）                                   出处 d078de1、c54538b（只加注释）
    go build -o derivedreport ./tools/derivedreport     ⛔ 必须编译后跑：go run 会把退出码 2/3 压成 1
    ./derivedreport -product SHFE.rb -from <起> -to <止> -store <库根> -days <交易日表> -spans <段文件>
    退出码：0 没有差异 · 2 有差异 · 3 比较窗口里一天都没判出来 · 1 失败（2 优先于 3）
    结构前提不过即停：段文件覆盖窗口里每个交易日 · 库打得开、没有残尾（检查在打开之前 —— segfile.Open 会截断）·
                      没有孤儿记录 · 没有旧格式 .meta · 盘上记录不少于 coverage 声称 · 逐根读得回
    覆盖层：段内没覆盖的天按相对 coverage 的位置转成洞（最后一段之后 ⇒ 尾部未登记；之前或两段之间 ⇒ 永久洞）；
            一份合约有洞，那一天整个品种就是无结论
    到期放行：合约已到期、没覆盖的那一截整个在最后交易日之后、库里最后一根 ＝ 最后交易日 ⇒ 不算洞
    每条差异印「先查什么」（处置表，design.md §十五「『还没定』乙的回答」）；每个处置动作都不走 derived
    ⛔ 只读：不写库、不写日历、不重拉、不回灌

四  判据的读数（docs/probe.md 6.21–6.32）—— 实现之前先写「会被什么读数证伪」，再取数
    问一  长假后首日那 6 天（2025-10-09 · 2026-01-05 · 02-24 · 04-07 · 05-06 · 06-22）主连夜盘根 0、量 0；
          第二来源：上期所成文的年度休市安排，6 天全部证实（6.23 之二、之三）
    问二  本库自建主连 vs 天勤主连：两条都有主连的 236 天上「非 a」集合逐天相同（对称差 0/0，6.30）
    问三  换月过渡窗口：窗口内 9 天里 NoPick 5 天、窗口外 232 天里 0 天；c 档 6 天落进 NoPick 0 天（6.31）
    真实库  SHFE.rb 2025-09-15…2026-09-11、24 份合约、988,197 根 1m 过一次工具（6.32）：
            判了 241 天 · a 230 · b 0 · c 6 · 无结论 5（全是规则没给出主力）· 差异 6 条（全是「base 有夜盘 · 观测没有夜盘根」）· 退出码 2
            判对的完整一行在跑工具之前落文，逐项全中；跑前跑后库整树 md5 不变

五  (*segfile.Store).Walk 仍不进 tickflow.Store 接口（用户 2026-09-17 定）                          出处 c54538b
    v0.6.0 注解写的是「第一个消费者是 v0.7 的 calendar/derived，那时再定」。实际的第一个消费者是 tools/derivedreport
    （derived 包本身只收数据、不收 Store）；它直接用 segfile，库里也还没有第二种 Store 实现 ⇒ 进接口换不来任何东西。

## 没做到的

```
一  calendar/embedded 看不见停夜盘这个已知缺陷【仍在】（TestKnownDefect_EmbeddedCannotSeeSuspendedNight）
    本版的 derived 只把这几天报出来，不改 base。修它要把交易所成文的年度休市安排作为另一个入口注入 calendar/embedded，
    要人拍板，不在 v0.7（design.md §十五「还没定」丙）

二  v0.6.0「没做到的」四（洞是永久的、库没有「补一段」的入口）⇒ 本版答的是【derived 不要】，不是【库有了】
    derived 只读不写；库侧的洞照旧只有「把该周期的 .dat 与 .meta 一起删掉，按交易日从早到晚重拉」一条出路
    （design.md §十五「开工条件二的回答」）

三  主连不落库、没有 View：「信号用复权价，成交用真实价」的 RawClose / Contract() 是 v0.9（Feed / View）的承诺
    今天要真实价：Continuous.ContractAt(i) 拿到第 i 根属于哪个合约，再回那个合约自己的库读原始根

四  到期放行规则只认 SHFE.rb；01 / 02 月合约一律不适用（「春节月份交易所可另行调整」）
    ⇒ 这两个月的合约没有独立来源核它的最后一根；6.32 里它们没影响任何一天的结论
    ⏰ 挂起项（design.md §十五「挂起项」丁）：以后读数里 rb 的 01/02 月合约出现尾部未登记或永久洞 ⇒ 查上期所当年的通知作第二来源

五  读数的射程：一个品种（rb）· 一年 · 一种换月规则（ByOIAndVolume）· 一种复权（NoAdjust，判夜盘只看量）
    问三一年只有 3 次换月 ⇒ 读数不是结论；问二的对照只在 236 个两边都有主连的天上
    FixedBarDaysBeforeExpiry 要的到期日由调用方填，本版没有把 refdata 接到它上面

六  沿用 v0.6.0「没做到的」二、三、五、六、七、八里没被本版触及的各条（2020-05-06 之前的分钟历史 · CheckBars 无生产调用点 ·
    源旧响应中间缺行 · 没量的射程 · 未明的读数 · 合约级 Since 等）—— 本版没有动它们
```
