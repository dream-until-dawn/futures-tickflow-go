# 使用者接入与维护手册

2026-11-12历史兼容核心和LU 2021日历已合并推送主线，基线3c8eae5；尚未打新的发布tag。新增官方历史Source、逐日证据日历、历史目录和批次原件编排的接入说明见[历史行情消费者说明](historical-dataflow-consumer.html)，真实样本、分期历史时段缺口与全量验收边界见[扩展状态](historical-dataflow-status.html)。消费方须固定软件完整SHA和数据SHA，合并主线不自动构成全历史保证。

本文面向回测引擎、行情研究程序和接入维护人员，说明当前可以依赖什么、需要自行承担什么，以及出现异常后如何处置。核对日期为2026-11-03，生产代码基线为 `16a0db0160d61eac16f7de235fc597045a7062cc`；本次只改文档及证据索引。它是持续维护的使用者入口，不是完整v0.11发布证明，也不是数据质量或收益保证。当前按[阶段交付范围](staged-delivery-20261029.md)提供能力，暂不打tag。

## 1. 项目在使用者系统中的位置

典型历史链路为：数据源 → Syncer校验与同步 → segfile持久化 → Feed逐根回放/聚合/指标 → 使用者策略与回测引擎。也可以实现BarWalker，向Feed提供自己的行情；只有实现Store接口还不够，Feed消费的是BarWalker。

本项目负责行情表示、交易时间模型、取数、同步、回放和计算；不负责下单、撮合、成交优先级、滑点、手续费、保证金、资金管理或自动结算。行情价格用float64，不在这一侧计算金额。独立adapter仅连接固定版本记账内核，不能据此推导交易闭环已经验收。

| 模块 | 使用者可获得的功能 | 不应推导出的能力 |
| --- | --- | --- |
| 根包tickflow | Bar、Symbol、交易日与周期接口；Syncer；Feed、View、聚合和指标消费接口 | 通用回测撮合引擎、所有任意周期组合 |
| source/shinnysource | 具体合约1m历史；已完结1m实时流 | tick逐笔、盘口、日内主连历史源、CTP交易握手 |
| source/sinasource | 具体合约日线；按源规则处理结算缺失 | 新浪分钟源实现、无限历史、主连Symbol输入 |
| source/cffexsource | 中金所具体合约日线和结算价 | 全交易所官方日线、所有品种相同上市日 |
| calendar/embedded | 当前品种时段模板，注入交易日及停夜盘名单 | 内置官方交易日库、历史全制度时段、自动查公告 |
| calendar/derived | 从1m数据判断夜盘并报告与注入日历的差异 | 自动生成或修改官方日历 |
| store/segfile | 单合约单周期文件、coverage和走查 | 数据库服务、跨进程锁、网络文件系统一致性 |
| continuous | 日线选约、换月、复权；供主连Feed读取 | 日内主连Feed、自动持仓换月交易 |
| indicator | MA、EMA、MACD、KDJ、RSI、CCI、BOLL；支持扩展指标 | 与所有期货软件逐值相等 |
| adapter独立模块 | 未复权具体合约行情到固定futsim.Bar的转换 | 撮合、拆根、结算或全部Bar字段透传 |
| tools/ | 探针、离线审计、现场准备、采集监护、证据封存 | 根库稳定API、已启动的常驻采集服务 |

## 2. 数据源、覆盖与外部依赖

### 2.1 取数范围

| 源 | 当前实现输入 | 主要限制与选择方式 |
| --- | --- | --- |
| 天勤 | 具体合约1m | 需要快期账户和显式OAuth客户端配置；历史数据需分页。日历模板覆盖从2020-05-06开始，更早数据即使上游存在也不是本库可交付范围。主连请求被拒绝 |
| 新浪 | 具体合约日线 | 深度和结算可用性按品种、合约、区间核实；上游主连或分钟探针读数不等于生产源支持。三位郑商所代码的年份歧义必须处理 |
| 中金所 | 具体合约日线 | 官网XML按日期请求，不是一次全量；2016-01-04是存档级观察，不是后来上市品种的有效起点 |

每次使用Source先检查Caps/Supports及请求范围，再检查返回结果。能力声明和历史探针均不是未来上游SLA，也不保证每个合约在全部日期有数据。区分“不支持”“请求失败”“完整成功但无数据”和“有数据”；不能都记成空数组后继续。

天勤Client配置中的Calendar、HTTPClient、ReadTimeout以及账户和客户端字段须显式提供；New本身不联网，第一次取数才建立会话。HTTPS认证、名称服务和WebSocket握手使用注入的HTTPClient；其Timeout不能代替握手之后的逐次读取期限。生产连接使用Go及coder/websocket v1.8.15，不是CTP交易前置连接。凭据不得写入源码、执行单、日志或工单；使用者负责其服务权限和可持续使用条件。

### 2.2 日历是输入数据

使用者提供准确的交易日列表；工作日不等于交易日。夜盘归属交易日可能跨周末和节假日，不能用自然日加一推算。embedded未收录的品种、模板有效期之外或注入表之外应保持不可回答，不补猜默认时段。

有停夜盘公告时，`embedded.New(days, embedded.NoNightAfter(...))`接收的是公告所说“该自然日晚上不进行夜盘交易”的日期。名单作用于所有有夜盘品种，不能表达同一天各交易所不同安排。Source、Syncer、Feed必须使用一致的日历；只给其中一个注入名单不够。derived只提供差异线索，不能用行情里没有根反向确认官方休市。

## 3. 核心字段与数据语义

| 字段/概念 | 应如何使用 | 容易误用之处 |
| --- | --- | --- |
| Symbol | 内部使用规范交易所、品种、年月；向原生接口输出时使用Native；ParseNative按数据自身交易日展开 | 郑商所三位码跨十年有歧义；不要以当前日期解码旧数据 |
| TradingDay | 所属交易日，不是Ts的自然日；请求From/To按交易日闭区间 | 夜盘按自然日分组会导致日线、结算错位 |
| Ts/TsEnd | 开收盘墙钟毫秒；展示与业务日期按东八区解释 | Duration是墙钟跨度，跨休市时不等于交易分钟长度；不是微秒或秒 |
| OHLC | float64价格；跨源对账须确认同合约、周期、口径 | float64不用于金额核算；复权价不能直接用作真实合约成交价 |
| Volume/OpenInterest | 手数，字段为float64；需整数时使用Lots并先验证有限性 | Lots对非有限值返回0，不能靠它区分缺失和真实零 |
| Turnover | 源不给时为NaN；当前新浪、天勤该字段缺失，中金所按源提供 | 老版本落库可能为0，不会因升级自动改成NaN |
| Settle | 日线可用性取决于源；分钟线或分钟聚合日线为NaN；缺失不能用于盯市 | HasSettle不是任意数值合法性的全套检查，接入资金系统仍检查有限、正数及业务约束 |
| FlagPartial | 已知不完整；调用方显式拒绝或记录接纳策略 | 不带标记不是外部市场完整性的绝对证明；零成交占位规则不同会影响缺根判断 |
| FlagAggregated/FlagSrc* | 标记聚合和来源，用于审计与对账 | 拼接不同来源前必须核口径，不能只看时间连续 |

本库交付Bar的契约是已完结根，不是滚动中的最后一根。已完结是按各入口判据得出的结论，不能推导成上游永不修正。缺失值不填零；NaN与阈值比较不会自动报错，使用者必须显式检查，否则策略可能一直不触发。

## 4. 同步、持久化与可复现回测

### 4.1 同步验收

`NewSyncer`创建编排器，`Sync(ctx, req, now)`返回报告和错误。验收不能只检查err：读取Complete、Incidents以及Gaps、Halt等结构化明细；有已覆盖跳过、缺口、走查未完成、旧元数据处置或截尾时，按报告决定是否可进入回测。Complete代表本轮已登记异常为空，不是全市场无遗漏证明。不要通过匹配Incidents的人类提示文本建立业务分支。

coverage记录按交易日“问过且满足本地完整成功条件”的区间，不保证交易所永不更正数据。只有OutcomeComplete可扩coverage；失败和未知不能当成确认无数据。重复Sync会跳过已覆盖日，不能拿它作为强制刷新历史修正的接口；当前没有已实现的通用强制覆盖更新能力。

回测应固定：源码/模块版本、日历和停夜盘名单、数据源与取数时间、合约、周期/聚合规则、原始库快照与哈希、指标参数与口径、策略和执行模型。历史数据升级或重拉后建立新快照，独立核对差异，再决定哪些回测结果作废。

### 4.2 segfile维护边界

- 每个Store是一个合约的一个周期，对应.dat与.meta；周期名使用PeriodDirName，不能用String自行拼路径（Windows上的1M与1m会冲突）。
- 当前没有跨进程锁，也没有并发安全承诺。由调用方保证同一命名空间仅一个写者；同步与回放错开，或在完整快照上回放，不在活跃写入文件上做复制。网络盘及跨机器并发没有保证。
- Open可能创建文件并处理残尾，不能把它当无副作用的只读检查工具。先备份/封存原件，保留截尾数和OpenState诊断。当前segfile不提供可依赖的OpenReadOnly公共入口。
- coverage走查会核数据与元数据的一致性；它不证明价格是真实成交，也不能抵御恶意同时改写数据和清单。损坏库先保留，不手工补齐.meta或填假根以通过检查。
- 没有自动历史更正迁移器。需要重建时在新目录完整同步、比较后切换，保留旧目录；本手册不建议直接删除唯一副本。重拉也不保证上游一定返回修正值。

## 5. Feed、周期与指标的消费契约

### 5.1 生命周期与错误处理

具体合约模式把BarWalker交给NewFeed；主连模式由Main.Walker供根，src必须为nil。From/To必须完整落在一段coverage中，Rule必须显式设置；Feed不自动缩小请求区间。Feed不是并发安全的，一个实例由一个消费方推进。

NewFeed先走查，Next再读取；第二遍失败时，ErrFeedVoided意味着已交出的回放根也作废。使用者应在一次回测完整结束且Close/Err检查成功后，才发布该次结果。不能把前半段盈亏当作有效最终结果。Close必须执行；提前结束也要关闭，关闭过程可能仍须走查余下数据，不承诺常数时间。

下面是可编译的回放封装；src、cfg以及consume中的策略约束由调用方提供，消耗结果须先缓存在本次回测上下文，成功返回后才对外发布：

```go
package consumer

import (
    "errors"
    tickflow "github.com/dream-until-dawn/futures-tickflow-go"
)

func Replay(src tickflow.BarWalker, cfg tickflow.FeedConfig,
    consume func(tickflow.View) error) (err error) {
    feed, err := tickflow.NewFeed(src, cfg)
    if err != nil {
        return err
    }
    // 即使策略提前失败，也检查关闭和读库错误。
    defer func() { err = errors.Join(err, feed.Close(), feed.Err()) }()
    for feed.Next() {
        if err = consume(feed.View()); err != nil {
            return err
        }
    }
    return feed.Err()
}
```

consume中先检查视图Valid、Ready、Defined、实际使用字段的有限性与Flags；这些状态含义不同，Ready不替代字段级校验。Prev受Lookback约束，越界视图无效；不要持有旧View并假定其历史窗口会无限保存。无效View的Bar返回零值，不是NaN价格根，所以必须先检查Valid；价格访问器的NaN语义不能套在Bar返回值上。Ready/Defined读的是序列当前进度，不是保存该View时的状态，需要历史状态时由使用者当步记录。

### 5.2 多周期与日线

| 选择 | 行为和约束 |
| --- | --- |
| AggTradingAxis | 按品种交易时间轴和相位聚合；墙钟跨度可能跨休市，不能以Duration判断分钟数 |
| AggClockGrid | 按时钟网格聚合并裁至最后交易分钟；只接收当前实现允许、整除480分钟的周期，不代表任意周期 |
| 日内辅周期 | 长于主周期且为其整数倍；TF只看到最后已收盘格子，不能用于预知尚未收盘的辅周期 |
| Daily辅周期 | 默认由主周期按交易日聚合，无结算价；指定DailyWalker时从日线源读，缺当天日线就无效，不自动补猜 |
| 聚合完整性 | 整格无输入不出根；有输入但缺分钟标Partial；部分标记向上传。零成交不占位的源可能把无成交与缺失混淆 |

同步已完成的基础数据不等于高周期口径正确。交易时间轴与时钟网格不能混接；同边界但不同数值算法可能无法自动识别。聚合OHLC为首开、最高、最低、末收，量额求和（任一NaN会传播），持仓取末根，结算价不凭分钟线生成。

### 5.3 指标与主力连续

指标默认CN口径，另有TV口径；“CN”不是与文华、博易、快期逐值对账通过的声明。EMA、RSI、MACD等递推指标依赖起始样本，单个短寿命合约的日线可能不足以消除起点影响。Feed自动预热会受coverage起点夹断，Ready如实反映不足；Defined、Settler收敛和数值有效不能互相替代。Settle处误差契约也不是逐位相等保证。

continuous支持按持仓、成交量等规则选约和多种复权，零值默认比例后复权RatioBack；主连Feed只接受日线，不提供日内主连。NoPick不猜合约。使用者记录Rolls、Contract、IsRollDay、Basis及所选规则；换月成本、平旧开新及持仓转换由执行引擎承担。前复权可能重写历史，RewritesHistory需纳入重算判据；复权序列可用于研究，不能当实际合约成交价格。

## 6. 实时衔接是可选能力

纯历史回测不需要连接Live。实时衔接唯一支持路径为：历史Feed的Next耗尽且Err为空 → PushFrom取得下一格 → Client.Live → Next得到已完结1m → Feed.Push；仅当stepped为真时主周期推进。不能以nil历史源构造纯实时Feed，也不能把未完结高周期根推入Push；主连模式或配置DailyWalker的Feed不支持Push。

Live一个实例对应一个具体合约，调用方持续消费并关闭。内部重连有界；起步及断线补回历史不全会报错。Live不写Store，后续持久化仍靠历史Sync。非末根按下一根出现判完结，时段末根依赖本机时钟及G（默认4秒）；四秒是策略参数，不是无条件延迟SLA。不要直接用偏慢的本机now对Live结果执行历史CheckBars而误判未来根。

| 情形 | 使用者动作 |
| --- | --- |
| ErrPushGap、断线补齐失败、消费者积压 | 记录错误阶段和起始格；按PushFrom及错误契约重新建立Live，反复失败暂停，不跳根继续 |
| ErrChannelsDisagree | 两通道不一致时不发布该段，保留证据，稍后独立核对 |
| ErrCorrectedAfterDelivery | 旧Feed已经消费的值不能回滚；废弃这次状态，待定型后从历史同步并重建，不能只重连Live |
| ErrClockSkew、疑似冻结、陈旧快照 | 停止依赖该流，核对时钟、实际交易安排与连接；不将未知当成正常零成交 |
| ErrFeedVoided | 本次读库结果作废，检查并固定数据快照后重建 |

详尽错误清单与实时契约见[contract.md的实时一节](contract.md)。普通夜盘的实测不能关闭停夜盘特殊窗口的风险。

## 7. adapter与记账内核

adapter是独立Go模块，唯一转换入口为 `adapter.Bar(tickflow.Bar, tickflow.Symbol) (futsim.Bar, error)`。固定futsim版本为 `v0.0.0-20260923031436-6d3c7bbf3347`，decimal为1.4.0；固定内核Advance只做守卫和计价，不撮合。

转换包含规范实际合约、交易日、毫秒到东八区时间、有限High/Low/Close到decimal。非法合约、非有限消费价格拒绝；Open、Settle、Volume、Turnover、OpenInterest和Flags不传递。正数、价格范围、正时长和整根处于连续时段等业务守卫在下游；日线或跨休市根不能直接当盘中输入。FlagPartial不会被adapter自动拒绝，调用前必须自行决策。

主连RawClose只恢复收盘，无法把复权后的High/Low还原成实际价格；不能与其拼成一根。需要按当日实际合约获取完整未复权OHLC。资金计算放在decimal侧，使用者自行提供正确乘数、费用、结算规则及合约参考信息，不能把refdata的存在当成这些信息已自动消费。

安装时显式固定根模块和adapter版本；依赖模块中的replace不会传给使用者，仓内replace只能用于开发。[adapter说明](../adapter/README.md)和[API迁移记录](release/v0.11.0.md)提供已验证的提交伪版本。`embedded.New`增加可变选项后，直接旧调用仍可用，旧单参数函数值赋值需包装；不能笼统称所有源码兼容。尚未创建阶段发布标签，不建议用随时变化的main作为可复现回测的版本。

## 8. 置信度与证据覆盖

不使用虚构的百分比。以下四类分别回答实现、有限实测、推断和缺失情况，不能互相代替：

| 类别 | 可以得出的结论 | 不能得出的结论 |
| --- | --- | --- |
| 代码及离线正反验证 | 已实现接口在测试输入、边界和故意破坏场景中的行为可复查 | 所有输入正确、与市场永远一致 |
| 有限现场观测 | 指定合约、时间、源码和网络环境下曾发生的可复核事实 | 全品种、全时段、全部未来窗口保证 |
| 条件推断 | 在明确假设下估计或解释结果 | 假设本身已被独立证明 |
| 未完成/未验证 | 知道缺什么，并保留阻塞或使用限制 | 用合成、历史或相邻窗口宣称完成 |

| 范围 | 当前证据 | 剩余限制 |
| --- | --- | --- |
