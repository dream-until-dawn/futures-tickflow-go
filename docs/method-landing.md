# 方法论落点表：**新学到一条规矩，它该落在哪**

这份文件不是方法论清单。**清单没用**——三十条塞进一份没人打开的
`METHODOLOGY.md`，只是把「只存在于对话里」换成「只存在于一份没人读的文件里」。

这份文件回答的是另一个问题：

> **有五六个时刻，人会真的伸手去做一件容易做错的事。
> 那一刻他手边打开的是哪个文件？规矩就写在那个文件里。**

所以本表只有两列有用：**落点**（那个时刻）和**载体**（那一刻打开的东西）。

## 二、落不进去的（第③类）——**这是合法结果，不是遗漏**

写下来的理由：

> **本表里【只能靠人】的失效现在有三条**（另两条：编造一个拆解、消息里的松）。
> 评审方那句该原样留着：**知道边界在哪，比把网织得更密有用。**
> ——「往更宽的网加」这个方向已经到头了，再加只会让人以为那一格有人守。

**「查过了，不适用」和「没查」长得不一样。**

> **第一条的两个实例，双方各一（2026-09-08）：**
> 我在消息里写「这一层没有『哪句被锚住』，**是全部**」，而文档里一直写的是有射程的版本；
> 评审方在消息里写「（原表 85，**口径差**）」——那句**从没进过任何文档**，
> 所以**没有任何机制会碰它**，而它正是他转手一个未验解释的那一次。
>
> ⇒ **两次都是：文档里守着射程，消息里松了一档，而松的那一档没有任何东西会发现。**
不写，下一次审计会把同一格再问一遍，并且会以为是漏了。

| 规矩 | 为什么落不进仓库 |
|---|---|
| **一个措施的价值边界，要和措施一起写下来** | 两半：**上界**——开方子时写「**这个方子挡不住什么**」；**下界**——立检查时写「**它在什么条件下才提供新信息**」。**两者的失效形态相同**：不写上界，别人以为它管住了没管的；不写下界，**它坏掉时没人发现，因为它平时本来就不产生信息**。⚠️ 落不进去的原因和「说『我做不到 / 分不开』时」那条一样——**使用现场是一句话被写下的那一刻，而那一刻没有闸门**；**而且它比那条更难抓**：那条至少有关键词可以扫（「做不到」「分不开」），**这条没有任何字面特征**。⇒ **两个实例写在这儿当钩子**（2026-09-08，双方各一）：**【上界】** 评审方给 `guardNames` 开「登记名字」这个方子时，漏了他自己三轮前说过的「只登记名字的守卫，挡的是改名，不是改值。**存在 ≠ 一致**」——**方子交出去了，而「它挡不住什么」没交**。**【下界】**「合并前重跑全套」这道检查，提供新信息的条件是**「这次合并不是快进」**；这个条件没写下来，于是它坏掉那一次没人发现——**它平时的输出和好的时候一样（都是「跑了」）**。⚠️ **而这条规矩最需要钩子**：评审方给这个形状命了名，**然后在下一段就犯了它**——因为他把它记成了一条【观察】。**一条越通用的规矩，越需要一个具体的实例，否则它只在被引用的那一刻存在。** |
| **「消息里的措辞比文档里宽」** | ⬇️ **排第一条，因为它落不进去的原因和其余几条不同**：其余几条是「**执行它需要两个人**」，这一条是「**它发生在工件之前**」。消息不会被 `grep`、没有守卫、下一个人也不会读到——**而规则和结论都是先在消息里成形的**。⇒ 消息是这条链上**唯一没有守卫、却又是所有东西上游**的那一段 |
| **载体里的规矩「以字节不变的方式」失效** | 评审方的攻击 A：把一条已登记规矩用 `<!-- -->` 包起来——**那一行一个字节没改**，两张表都对得上，而渲染后它不见了。禁注释关掉的是**一个已知入口**，不是那一类。**已实测两种不含 `<!--` 的写法**：**A2** 那一行前后各加一行围栏 → 渲染成代码块 → 全绿；**A3** 只在行首加四个空格 → 同样渲染成代码块，而 `ruleLines` 先 `TrimSpace`，登记表照样认得 → 全绿（对照：真删那一行 → 红，所以这两个绿不是仪器坏了）。还有没试过的：改渲染标记、挪进已有代码块……**只要不动那一行的字节，两张表就都不响**。唯一有意义的度量是**渲染后的文本**，而那要引入一个 Markdown 解析器——**引入之后这套守卫的可信度就取决于那个解析器，而它没有守卫** |
| **可见 ≠ 可读**：一个字的语义反转，diff 尺寸等于一次润色 | 评审方 2026-09-08 把 `CONTRIBUTING.md` 一条规矩里的「不」字删掉——「**不写**，它就会变成又一个『看起来那一格有人守』的东西」变成「**写**，它就会……」。重生成后**全绿**，`diff --numstat` 是 `1 1` + `1 1`，**和一次错别字订正完全一样**。⚠️ **这一条与上面三条不同**：上面三条是**守卫够不着**，这一条是**守卫做到了它能做的全部，剩下的在读 diff 的人身上** |
| **散文里的版本号：同一个数字，一个是历史陈述、一个是活指针** | **（2026-09-08 当时）**同一段引用块里 `v0.3` 出现三次——⚠️ **这句话本身就是一条历史记述，而它此前没留时态标记**：`8f19688` 把其中两处改成了指代 ⇒ 计数变成 1；`dad880f`（里程碑整体后移）又把剩下那一处改成 `v0.4` ⇒ **今天那里一次也不出现**。**写这一行的人（我）刚写完「写历史记述要①用指代②留时态标记」，然后在同一行里漏了②。** 例子如下：「排期**第一版**把 X 放 v0.3」是**关于旧文档说了什么**（改了它，那句话就变成假的）；「X 留在 v0.3」是**指向现行排期的活指针**（不改它，它就指向错的一档）。**分辨要读懂上下文，没有语法标记**——`ruleLines` 也够不到：那几行是引用块续行、不含 `**`，**把 `docs/design.md` 列为载体也盖不住它们**（实测：35 行含版本号，只盖到 11 行）。⚠️ **而改错的后果不是变红，是把一段【教训的证据】改成假的，只留下结论。** ⇒ **处置是【两条】动作，不是「承认守不住」：写历史记述时 **①用指代**（「两档之后」）不要写版本号，**②留一个时态标记**（「排期第一版」「当时」「后来改了」）。⚠️ **②是①的必要配套，不是锦上添花**——只做①，下一个人仍然无从判断这句是历史还是现行，**而他连版本号这条线索都已经没有了**。对照：`1906` 有「排期**第一版**」这个显式时态标记，所以它是历史；`docs/design.md`「时机取『现在』而不是『v0.3 一起改』」**没有**，于是两种读法都讲得通——**那正是「必须问」的定义**。 2026-09-08 已把 `docs/design.md` §十五 那三行改成指代——**同一个引用块里本来就有一句是这么写的**，不是新发明一种写法。**但拿掉实例不等于拿掉类**：下一个人还会写新的历史记述，而他手边最顺的写法就是写版本号。⇒ 真要判一次时的判据：**把两种读法各自代入【位移之后】，看哪一种留下的句子对读者仍然为真。** |
| **一个守卫被【掏空】或 `t.Skip`：名字还在，事不做了** | `guardNames` 登记的是**名字** ⇒ **存在 ≠ 一致**（评审方 2026-09-08 提出，我实测两种：函数体掏空 → PASS；开头加 `t.Skip()` → PASS，而自检用的 `go test ./... -count=1` 是非 `-v` 的，**SKIP 连显示都不显示**）。**掏空一个守卫和删掉一个守卫，后果一样，而只有后者会响。** ⚠️ 不做哈希登记的理由不是做不到，是**每一次【合法】修改守卫都要重生成**——**摩擦落在最该被鼓励的动作上**，那种守卫迟早被绕开。⇒ **这一格没有机械守卫，只有对照组**：**一个被掏空的守卫，就是一台悄悄停了的仪器**，而唯一能看见它的东西是那台仪器的对照组。⇒ **「每个守卫要有一格能重跑的对照组」不是可选项，是这一族的终点。** |
| **评审六维度、结论三种、评审方不改代码只给 `file:line`** | 这是**评审方**的动作。写进本仓等于本仓替评审方规定他怎么审——而他的独立性正是他的价值 |
| **「复查同一条路的第二双眼睛没有价值」** | 判断两条路独不独立，需要**同时知道两条路**。仓库里只有一条 |
| **「评审方的无知是资源」** | 它规定的是**读代码的顺序**（写完自己的断言之前别看实现）。§14.1 里只能写下这条顺序，**执行它需要两个人** |
| **「事后主动说 ≠ 事前确认」** | 落进 `CONTRIBUTING.md` 的只是「动手前问」这个动作；**「问了之后要等」** 需要对面有人 |
| **「一条被丢弃了输出的命令，不能当已完成的依据」** | 已经变成动作而非规矩了（`CONTRIBUTING.md` 要求贴真实输出）。作为**规矩**它落不进去：没有任何检查能发现你 `2>/dev/null` 了什么 |
| **「说『我做不到 / 分不开 / 想不出』」时** | 使用现场是**一句话被写下的那一刻**，而那一刻没有闸门。已落的只有半道：`CONTRIBUTING.md` 要求送审材料里这类词必须紧跟「再做一次要多少钱」——它抓不全，但抓的正是**会传到第二个人手里的那些** |

> ⚠️ **原本这里有第六条「编造一个拆解没有机械守卫」，评审把它挪走了，他对：**
> `tools/audit/` 那条规矩就是那道闸门的一半——**凡是写进 `probe.md` 的数字，
> 若不是探针输出，产生它的脚本要落盘**。一个数字若有脚本产出，
> **拆解就是脚本打印的，编不出来**。剩下的那一半（散文里仍然可以编）才是「只能靠人」。
> ⇒ **「没有机械守卫」和「机械守卫只盖住一半」是两回事**，而前者读起来像已经想过了。

## 三、这次审计**审到哪一步为止、按什么来源审的**

> 一次审计的完整性受限于它用的来源。**「审计过了」这句话必须说清按什么来源审。**
> （这条本身就是被一次审计漏掉的东西逼出来的：一边用等号式模式扫、一边用散文式扫，
> 各自漏掉对方那一批。）

**我用的来源，三样，按可靠性从高到低：**

1. **仓库现状**——`grep` / `ls` 出来的，不是回想的。落点表第三列「你此刻会打开什么」
   全部是这么定的：**先问那个目录里现在有没有文件，再问它说了什么。**
   （`tools/probe/README.md`、`docs/README.md`、`CONTRIBUTING.md` 三处此前**不存在**，
   是这么发现的，不是想出来的。）
2. **我自己对这几轮工作的记忆**——不可靠，且**系统性地偏向我提出的那些条目**。
3. ⚠️ **共享 memory 里那份评审记录**（`futures-tickflow-review-gate.md`）。
   我今天读了它，它含评审方编号的那批条目。

**第 3 条要单说，因为它改变了这次审计的性质：**

原本的分工是「我按我的来源起骨架 → 评审方拿他的清单补差集」，
**理由是两边各扫一遍才是两条独立的路**。而我读了他那份记录之后，
**这两条路已经共用了一个来源** ⇒ 按本仓自己的判据（两条路独立与否，
看它们会不会因为同一个原因同时错），**他再拿同一份清单来对，就是同一条路的第二双眼睛。**

⇒ 所以第二遍必须换出发点，不是换人：**别对着这张表挑缺什么**（那是同一条路），
**而是冷着走一遍每个落点，先写「在这一刻，一个赶时间的人最可能做错什么」，
再回来看这张表拦不拦得住。** 从失败场景出发和从清单出发，
**不会因为同一个原因同时漏。**

### 覆盖面的机械定义，**以及它量错过一次**

逐条登记表覆盖的是一个**数得出来**的集合，不是「我记得锚住了哪些」：

```
载体文件里   ① `> ` 引用块中的加粗行     ② 独立成行的加粗句
```

⚠️ **第一版只认 ①，漏掉 11 条 ②**——其中就有 `CONTRIBUTING.md` 那条
「把「哪一刻的快照」写进快照本身」。发现它靠的是一次**打不中目标的变异**：
我去改写一条「已登记」的规矩，`assert` 报找不到，才知道它根本没被登记。

> **「它有一个机械定义」这句话本身，也可能是一个「看起来像守住了」的东西。**
> 定义要和文件里**实际用的格式**对齐，而那要数一遍，不是想一遍。

**仍然盖不住**：写成普通行文、加粗只在句中的那些。我判断它们多半是解释而不是规矩——
**但那是判断，不是测量**，所以它进上面那张表的 ❌ 行。

> **一个「由模式生成」的登记表，它的覆盖面永远只能被【另一个模式】测出来。**
>
> ⚠️ **同一句的第二次应用，2026-09-08 晚**：为了治「下限随规模变松」，
> 我把下限改成了 `int(当前条数 × 0.9)` ——**而那是从【被守的量】派生出来的**。
> 实测：删掉一整节规矩 + 重生成 ⇒ **全绿**，下限跟着掉。
>
> **一个从被守的东西派生出来的阈值，不是阈值。** 它在生成那一刻恒真，
> 只在两次生成【之间】有力气，而正常流程从不留下那个窗口。
>
> 而最该记的是评审方那句自我更正：**「我抱怨的『陈旧』，恰恰是它唯一的独立性来源。
> 我把陈旧修掉了，连带把它的功能修没了。」**
>
> ⇒ **凡阈值，先问它是从哪儿来的。** 从被守的量派生 ⇒ 它守的是「派生动作没发生」，
> 不是那个量；而正常流程恰恰总是让派生动作发生。
>
> 生成器和验证器用同一个模式 ⇒ **它对自己永远自洽**。
> 我曾有 76 条登记、44 节锚点、五种拆除验证**全绿**，
> 而当时实际漏着两条——**因为那五种拆除也在同一个模式内部**。

#### R4（挪节）：**他说可以只写取舍，我选择修**——而他给的降级理由有一条站不住

他压低严重度的两条理由：
① 挪动在 diff 里**是可见的**（一删一加），而改写不可见；
② 触发它要一个比「顺手润色一句」奇怪得多的动作。

**② 成立**（那是关于概率的），**① 不成立**：**改写在 diff 里同样可见**——
一行变了就是一行变了。而且如果「diff 里看得见」算防线，
**这一整套登记表就都不必存在了**——上面每一种攻击在 diff 里都看得见。

⇒ 所以修它。成本也确实低：**生成器为了锚点守卫本来就在跟踪小节**，
加一个字段而已。复跑：挪节现在变红，对照（真删那一行）也红。

#### 取舍：**我选了「把检查改成它宣称的样子」**（评审方委派我判）

| | 整行逐字比对（选中） | 保留前缀 + 改文案 |
|---|---|---|
| 那 859 字 | **受守卫** | 仍然自由 |
| 改一条规矩的措辞 | **必须重跑生成器**（多出来的手工） | 不必 |
| 文案与实现 | 对上 | 对上 |

**选它的三个理由：**

1. **这套东西的全部用途就是守规矩的文本。** 只钉前 26 字，钉住的是**标签**，不是**规矩**。
2. **改一条规矩的措辞，本来就该是一个显式动作**——它和「删掉一条规矩」在后果上同级，
   而删除早就是显式的了。让改写也显式，是把两件同级的事拉齐。
3. **重跑的成本已经被别的事情摊掉了**：`carrierCensus` 早就要求
   「加/删任何一个加粗短语都得重跑生成器」，而重建现在是**一条命令**
   （`tools/audit/rebuild_docs_test.py`，原子、失败即还原）。

**认下来的代价，说清楚：**

> 此后**改任何一条规矩的一个标点，测试都会红**，必须重跑生成器。
> 这会让「顺手润色一句规矩」变成一个带确认动作的操作。
> **我认为这正是想要的**，但它确实是**多出来的手工**——
> 如果将来有人觉得太吵，正确的动作是**回来改这一格的取舍并写明**，
> 不是给检查加豁免。

#### 所以加了一个**不带模式**的数：`TestCarrierCensus`

只数「每份载体里含 `**` 的行数」。删掉任何一条规矩它都会掉，
**不管那条规矩长什么样**。两张表因不同原因失效：

```
普查数   挡不住「原地改写」（行数不变）    挡得住「没进登记表的行被删」
登记表   挡得住改写（针对不上）            挡不住没进表的行被删
```

代价说清楚：**改这五份文件时，加/删任何一个加粗短语都会让它变红**，得重跑生成器。
这是有意的摩擦，同 `pending.txt`——**不这样，覆盖面就只能靠回想。**

#### 已验的一处**强项**：重生成的 diff 是最小的

评审方 2026-09-08 量的：改一条规矩的**一个标点** → 未重生成时红；跑
`rebuild_docs_test.py` → 绿，而 `docs_test.go` 的 diff 是

```
-  {`tools/probe/README.md`, ..., `探针不是测试。 测试断言…`},
+  {`tools/probe/README.md`, ..., `探针不是测试． 测试断言…`},
```

**一行进、一行出，正好是被改的那条。**

这一环要紧，因为**整条链的最后一环是「人读 diff」**——
而这一环的**信噪比就是守卫强度的一部分**。生成器是最小 diff 的，这一环没被稀释。

> ⚠️ 但**它到此为止**：见上表「可见 ≠ 可读」那一行。
> **守卫能让改动可见，不能让改动可读。**

#### 用一个和生成器不同的网扫过一遍（`tools/audit/sweep_carrier_rules.py`）

把五份载体里**每一行含 `**` 的行各删一次**（299 行），看守卫响不响：

```
2026-09-08 那次：扫了 350 行（最宽的网，与生成器的 is_rule 无关）
                没响的：0 行
                对照组：删 docs/probe.md（非载体）三行 → 3/3 绿
```

> ⚠️ **那个行数是快照，不是常量**——这几份文件一改它就变。
> 记它是为了「当时扫了多少」，不是为了拿来比对；**要现在的数就重跑那个脚本。**
> （`TestCarrierCensus` 才是钉住行数的那个，它每次跑都算。）

而**把生成器与验证器的判据统一**这件事，自己又出了一个 bug，且是测试抓到的：

```
**有些行根本不在登记表里。**       ← 16 个字符 / 40 个字节

Python  len(line) = 16   →  16 > 16 为 False  ⇒ 生成器【丢掉】它
Go      len(line) = 40   →  40 > 16 为 True   ⇒ 验证器【认】它
```

**同一个阈值 16，两边的单位不同。** 于是登记表少一条、验证器多认一条，
`TestEveryQuotedRuleIsRegistered` 当场报「多了一条没登记的规矩」。

> **两处「必须一致」的判据写在两种语言里，一致性就得自己有人守。**
> 这次守住它的是那条测试本身——**因为它比的是两边的【产物】，不是两边的【源码】。**
> 比源码要靠人读，比产物是机械的。

> ⚠️ **对照组这一步不能省。**「299 行全响」和「这个 harness 永远返回非零」
> **在输出上长得一模一样**。第一遍我跑出 0 的时候，harness 正在抛编码异常，
> 而我只用了 `returncode`——**一个favorable 的结果配一个没验过的仪器，
> 正是这份文档从头到尾在讲的那件事。** 重跑：改成 bytes，加对照组。

**上表那三个 ❌ 是这张表最诚实的部分。**

- 「那个文件其实没人打开」——**落点是我猜的**。要量它，得看真实的编辑记录，仓库里没有。
- 「新规矩只在对话里」——**这张表治不了自己**：一条没进表的规矩，
  表上看不出任何异常。这正是它被建起来的原因
  （「期望串别手敲」在对话里说过三次，`main` 的 `docs/` 里一个字都没有）。
- 「规矩写成普通行文」——**覆盖面的机械定义有边界，而边界在哪是我判断的**。

别把 ✅ 读成「守住了」。这张表挡住的是**腐烂**，挡不住**遗漏**。
