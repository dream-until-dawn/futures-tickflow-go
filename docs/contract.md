## 二、边界：明确不做的

| 不做 | 理由 |
|---|---|
| **期权** | 期权链 / IV / 希腊字母是另一个数据模型，会把 `Bar` 撑变形 |
| **组合 / 套利合约** | 它们的「价格」是价差，不是价格 |
| 逐笔成交 / 盘口深度 | 中国期货的 tick 是 500ms 快照而非逐笔，形态不同。命名空间已留位 |
| 涨跌停 / 保证金的**模拟** | `refdata` 给参数，怎么用是回测引擎的事 |
| 交易决策 / 仓位核算 | 下游的事 |
| **新浪实时行情** | **已冻结两年**（见风险表第一行），接了就是静默错误 |
| 上期 / 大商 / 郑商官方直连 | 实测被 WAF 挡（412），绕过要无头浏览器 |
| 多进程并发**写** | 一个命名空间一个写者，第二个拿 `ErrLocked`。并发**读**支持 |

`Feed` **不是并发安全的**——一个回测循环就是一条时间线。

## 三、置信度：每条结论是怎么来的

| 级别 | 含义 |
|---|---|
| **实测** | 打过真实接口，数字可重跑。重跑方式见 [probe.md](probe.md) |
| **推定** | 从外部**未文档化**的行为推出来的。上游改了不会通知谁 |
| **未验** | 还没测过。**写在这里就是为了不被当成已知** |

### 实测（2026-09-07）

| 结论 | 证据 |
|---|---|
| 新浪日线覆盖 17 年，含持仓量与结算价 | `RB0` 4237 根，2009-03-27 → 2026-09-04 |
| 新浪分钟线**每周期恰好 1023 根，无翻页参数** | 5/15/30/60m 四个周期全部 1023 |
| 新浪 K 线按**收盘时刻**标注 | 首根是 `09:05` 而非 `09:00` |
| 休市段**不占位** | `10:15` 之后直接跳 `10:35` |
| 高周期**跨休市段计数聚合** | 30m 的 `13:45` = `11:15–11:30` + `13:30–13:45` |
| 网格**跨隔夜缺口**，在交易日边界重启与冲刷 | `AG0` 60m 的 `09:30` = `02:00–02:30` + `09:00–09:30` |
| **同日盘的两个品种可以有不同的 60m 网格** | `AG0` `09:30 10:45…` vs `CU0` `10:00 11:15…` |
| **15m 上两种对齐规则结果相同**（验不出差异） | 三个日盘时段都是 15 的整数倍 |
| 新浪返回**未完结**的当前根，标签是**未来时刻** | 墙钟 13:19，30m 序列末根标 `13:45` |
| **新浪期货实时接口自 2024-07-17 冻结** | 六个字段与日线 2024-07-17 那根**逐位相同** |
| **主力连续 `RB0` 未复权，换月日虚增 1.7pp** | 08-28→08-31：`RB0` +2.73%，真实合约 +1.00% / +1.23% |
| 天勤 openmd 提供**按合约的交易时段表**，免费无鉴权 | 11845 symbol，9 种时段模式 |
| 夜盘跨日用 `25:00` / `26:30` 表示 | cu 组 21:00–25:00；au/ag/sc 21:00–26:30 |
| 中金所股指与国债时段**互不相同且都异于商品** | IC/IF/IH 09:30–11:30；T/TF/TS 09:15–11:30 |
| 天勤 websocket 路径存在但需鉴权 | `/t/md/front/mobile` 返回 **400**，其余路径 404 |
| 快期 OIDC 鉴权路径已确认 | 空密码返回 **422** 且指明 `password` 字段 |
| 四家交易所只有中金所可直连 | CFFEX 200；SHFE 404；DCE / CZCE **412（WAF）** |
| 郑商所 3 位码在新浪返回**空数组而非报错** | `TA701` 空，`TA2701` 154 根 |

### 推定

**外部未文档化，可能在不通知的情况下改变。**

| 推定 | 现状 | 变了会怎样 |
|---|---|---|
| 周期网格规则 = 「交易日内累计交易分钟等分 + 日末冲刷」 | 在 4 个周期 × 3 类品种上都对上了 | `SyncReport.Misaligned` 不为零 |
| 交易日边界在日盘收盘后、夜盘开盘前 | 由 `AG0`/`CU0` 的网格重启点反推 | 同上 |
| 郑商所 3 位码按「相对该数据所属交易日取最近的将来」展开 | 无官方说明 | 拉到错误年份的合约，或空 |
| 新浪 K 线接口会长期可用 | 目前活跃 | **它的实时接口已经死了两年**，K 线接口没有理由认为一定不会 |

### 未验（**尚不知道，别当成已知**）

| 未验 | 为什么要紧 |
|---|---|
| **快期账户下的深度分钟历史能回溯多久** | 决定分钟级回测的可行深度。**v1 的实时与深度历史全押在这上面** |
| 天勤 `KQ.m@` 主连的复权口径 | 若已复权可省一部分自研；**不能假定与新浪 `RB0` 一致** |
| 新浪与天勤同周期是否逐位一致 | 对不上就必须选一个当真值 |
| **交易时段的历史变更表** | 决定旧数据能否正确判完结。已知同品种不同合约时段不同，但**变更时点未测** |
| 国内期货软件（文华/博易/快期）的指标口径 | 决定 `indicator` 的默认口径。**未验前不设默认** |
| 新浪是否会修正历史数据 | 交易所会修正结算价，新浪跟不跟未知 |
| 停牌 / 熔断当日的数据形态 | 影响 `FlagPartial` 的判定 |

## 四、已知风险

**「是否静默」那一列最要紧**——会报错的问题不可怕，不报错的才是。

| 风险 | 静默？ | 后果 | 怎么办 |
|---|---|---|---|
| **新浪实时接口已冻结两年** | **是**（HTTP 200 + 数值合理） | 拿 2024-07-17 的价格做实盘或回测 | 本库**不接**。任何实时源必须带开机自检：与当日日线比对，对不上就报错 |
| **主力连续未复权** | **是**（序列平滑无标记） | 每个换月点凭空 ~1.7pp 收益/亏损，17 年上百个 | 用 `continuous` 自建并取 `Rolls`；新浪 `RB0` 只作对账 |
| **前复权会改写历史** | **是** | 同一段历史、同一策略，今天跑与下月跑**结果不同** | 默认后复权。要前复权必须显式选，且它会警告 |
| **拿复权价去算钱** | **是** | 手续费 / 保证金 / 涨跌停全错（后复权价位是虚构的） | **信号用 `Close`，成交用 `RawClose`**。这是本库对下游最重要的约定 |
| **时段表过期**（交易所改夜盘） | **半**（`Report.Misaligned` 会报，但要有人看） | 网格算错，**每一根都偏**，序列看起来正常 | 盯 `Misaligned`；用 `calendar/derived` 从数据反推 |
| **夜盘归属搞错** | **是** | `TradingDay` 错一天，结算与日线全部错位 | 周五夜盘属于**下周一**。有测试锁 |
| **交易所修正历史结算价** | **是** | 已落库数据与交易所不符 | `SyncRequest.Force` 忽略 coverage 重拉 |
| **不同源数据不一致** | **是** | 换个源回测结果就变 | `Bar.Flags` 记来源；对账前先看来源 |
| **郑商所 3 位码跨十年歧义** | **是**（新浪返回空数组不报错） | 拉到错误年份，或静默拿到空 | 内部一律 4 位；`RegisterCentury` 可覆盖 |
| 分钟历史只有 1023 根 | 否（`Caps` 会报） | 分钟级回测深度不够 | 接天勤（**待验**）；或从今天起累积 |
| 交易日历推不到未来 | 否（`ok=false`） | 实盘判断不了明天是否开市 | 用 `calendar/embedded` 的前瞻表或交易所公告 |
| 未完结 K 线 | 否（本库在 `Source` 层挡掉） | — | 需要日历才判得了，所以日历是硬依赖 |
| 停牌 / 熔断 | 否（`FlagPartial`） | — | 判定形态**尚未实测** |
| 跨进程双写 | 否（`ErrLocked`） | — | 一个命名空间一个写者。**跨机器 / 网络文件系统无保护** |
| `Feed` 并发推进 | 否，会乱 | — | 不是并发安全的，各建各的 |

### 一类特殊的风险：测试全绿但实现是错的

有些错误**挑错测试参数就永远照不出来**。已知两处：

**一、只测 15m 分辨不出周期对齐规则。**
三个日盘时段（75 / 60 / 90 分钟）都是 15 的整数倍，所以「交易时间轴计数聚合」
与「按时段对齐」在 15m 上**给出完全相同的结果**。一个写错的实现能全绿。
**必须用 30m 或 60m 测。**

**二、只测夜盘长度整除的品种，分辨不出网格是否跨隔夜。**
`CU0` 夜盘 240 分钟，对 30m / 60m 都整除，网格从日盘 09:00 干净地重开。
只拿它测，一个「日盘重新对齐到整点」的错误实现同样全绿。
**必须用 `AG0` / `AU0`（夜盘 330 分钟，对 60m 余 30 分）测。**

> 这两条都写进了 design.md 的测试策略。它们的共同形态是：
> **一个特例恰好让正确实现与错误实现产出相同结果。**
> 选测试数据时，要专门去找能把两者分开的那个参数。

### 跨库静默：本库不报错，但下游会得出错结论

| 情形 | 本库做什么 | 下游不看会怎样 |
|---|---|---|
| 同步时有交易日取不到数据 | 列进 `Report.Gaps` | 回测在缺了数据的区间上照跑，产出一个 P&L，没有提示 |
| 换月 | 列进 `Continuous.Rolls` | 把换月当天的基差跳空当成行情收益，且不计换月成本 |
| K 线不完整（停牌/熔断/聚合缺根） | 打 `FlagPartial` | 与完整的那些**长得一模一样** |
| 数据来源不同 | 打 `FlagSrc*` | 两段来源不同的数据接在一起，看不出接缝 |
| 指标未 warmup / 视图无效 | 返回 `NaN` | `if v.Ind("x") > 阈值` 在 NaN 下**恒为 false**，不报错也不触发 |

最后一条值得单说：NaN 是刻意的（0 是个看起来正常的价格），但**与 NaN 比较
永远是 false**。它挡住了「用垃圾值算出一个数」，挡不住「一个分支从此再没进去过」。
循环里用 `View.Ready()` 判，别靠比较。

## 六、怎么自己重新验证

**现在**（还没有库代码）能跑的只有探针。一条命令跑完全部 9 条实测结论
并与 [probe.md](probe.md) 的记录比对：

```bash
python tools/probe/probe.py
```

只用标准库，无需安装任何东西。2026-09-07 实测 9/9 一致。
退出码 `0` 一致 / `1` 有偏离 / `2` 网络或解析失败。

**它不进 CI 的必过项**——一个会因为新浪改接口而变红的必过项，
迟早会被加上 `|| true`，然后就再也没人看了。

要手工确认，最要紧的三条：

```bash
curl -s -H "Referer: https://finance.sina.com.cn" "https://hq.sinajs.cn/list=RB0" | iconv -f GBK -t UTF-8
```

看第 18 个字段（日期）。不是今天 = 实时接口仍处于冻结状态。

```bash
curl -s -H "Referer: https://finance.sina.com.cn" "https://stock2.finance.sina.com.cn/futures/api/jsonp.php/var%20_=/InnerFuturesNewService.getFewMinLine?symbol=AG0&type=60"
```

看日盘标签是不是 `09:30 10:45 13:45 14:45 15:00`。是 `10:00 11:00…` 的话，
说明网格规则变了，design.md 第二节要重写。

```bash
curl -C - -o tq.json "https://openmd.shinnytech.com/t/md/symbols/latest.json"
```

慢（约 12.5 MB，需续传）。看 `trading_time` 是否还在。

**将来**（有代码之后）：

```bash
go test ./...
go test -race ./...                      # Windows 需 MinGW-w64
FTF_LIVE=1 go test ./source/...          # 打真实接口
```
