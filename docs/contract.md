### 对外可见的常量与变量

**这些是【契约的一部分】**——用本库的人会直接写到自己的代码里：

```go
const (
    SHFE  = "SHFE"  // 上海期货交易所
    DCE   = "DCE"   // 大连商品交易所
    CZCE  = "CZCE"  // 郑州商品交易所
    CFFEX = "CFFEX" // 中国金融期货交易所
    INE   = "INE"   // 上海国际能源交易中心
    GFEX  = "GFEX"  // 广州期货交易所
)

// CST 是中国期货市场的时区（东八区）。
// 把 Bar.Ts（毫秒）换成墙钟时间时用它，别用 time.Local——
// 跑在别的时区的机器上，time.Local 会给出另一套小时数。
var CST = time.FixedZone("CST", 8*3600)
```

> ⚠️ **这一节是补的（2026-09-08），而它补的是一个「没人决定过」的状态**：
> `CST` 在源码里导出了三处、在文档里**出现过零次**；六个交易所常量在文档里被提了上百次，
> **但从来没有作为【声明】出现过**——散文里提到一个名字，和把它写进契约，不是一回事。
>
> 而 `doccheck` 照不到这个方向：它遍历的是**文档声明**，
> 所以「**源码导出了、文档一个字没提**」永远不会被报出来。
> ⇒ 这一格补的是**决定**，不是守卫：**要么写进契约，要么写明它不属于契约，
> 而现在这样是第三种——没人决定过。**（评审方 2026-09-08 提。）

## 二、边界：明确不做的

| 不做 | 理由 |
|---|---|
| **期权** | 期权链 / IV / 希腊字母是另一个数据模型，会把 `Bar` 撑变形 |
| **组合 / 套利合约** | 它们的「价格」是价差，不是价格 |
| 逐笔成交 / 盘口深度 | 中国期货的 tick 是 500ms 快照而非逐笔，形态不同。命名空间已留位 |
| 涨跌停 / 保证金的**模拟** | `refdata` 给参数，怎么用是回测引擎的事 |
| 交易决策 / 仓位核算 | 下游的事 |
| **新浪实时行情** | **已冻结两年**（见风险表第一行），接了就是静默错误 |
| **中金所品种基于新浪结算价的逐日盯市** | 新浪对中金所**全部八个品种**（IF/IH/IC/**IM**/T/TF/TS/**TL**）**系统性不给结算价**。2026-09-09 复测四个：`IF2609` 156/156、`IM2609` 156/156、`T2612` 122/122、`TL2612` 122/122 **全部为 0**。走 `cffexsource` |
| 上期 / 大商 / 郑商官方直连 | 实测被 WAF 挡（412），绕过要无头浏览器 |
| 多进程并发**写** | 一个命名空间一个写者，第二个拿 `ErrLocked`。并发**读**支持 |

`Feed` **不是并发安全的**——一个回测循环就是一条时间线。

## 三、置信度：每条结论是怎么来的

| 级别 | 含义 |
|---|---|
| **实测** | 打过真实接口，数字可重跑。重跑方式见 [probe.md](probe.md) |
| **推定** | 从外部**未文档化**的行为推出来的。上游改了不会通知谁 |
| **未验** | 还没测过。**写在这里就是为了不被当成已知** |

### 实测（2026-09-07）

| 结论 | 证据 |
|---|---|
| 新浪日线覆盖 17 年，含持仓量与结算价 | `RB0` 4237 根，2009-03-27 → 2026-09-04 |
| 新浪分钟线**每周期恰好 1023 根，无翻页参数** | 5/15/30/60m 四个周期全部 1023 |
| 新浪 K 线按**收盘时刻**标注 | 首根是 `09:05` 而非 `09:00` |
| 休市段**不占位** | `10:15` 之后直接跳 `10:35` |
| 高周期**跨休市段计数聚合** | 30m 的 `13:45` = `11:15–11:30` + `13:30–13:45` |
| 网格**跨隔夜缺口**，在交易日边界重启与冲刷 | `AG0` 60m 的 `09:30` = `02:00–02:30` + `09:00–09:30` |
| **同日盘的两个品种可以有不同的 60m 网格** | `AG0` `09:30 10:45…` vs `CU0` `10:00 11:15…` |
| **15m 上两种对齐规则结果相同**（验不出差异） | 三个日盘时段都是 15 的整数倍 |
| 新浪返回**未完结**的当前根，标签是**未来时刻** | 墙钟 13:19，30m 序列末根标 `13:45` |
| **新浪期货实时接口自 2024-07-17 冻结** | 六个字段与日线 2024-07-17 那根**逐位相同** |
| **主力连续 `RB0` 未复权，换月日虚增 1.5–1.7pp** | 08-28→08-31：`RB0` +2.73%，真实合约 +1.00% / +1.23%（探针打印 `1.50–1.74pp`） |
| 天勤 openmd 提供**按合约的交易时段表**，免费无鉴权 | 11845 symbol，9 种时段模式 |
| **网格相位是品种常量，停夜盘日不变** | 3 个停夜盘日 × `AG0`/`AU0`/`SC0`，日盘网格与普通日逐个相同 |
| **天勤深度：890,231 根 1m，回溯到 2016-01-04** | `KQ.m@SHFE.rb` 的 `last_id` |
| **已到期合约同样供得出完整 1m** | `rb1605`/`rb1801`/`rb2310`/`rb2410` 四个全中；`rb1605` 39,600 根、最早 2016-01-04 |
| **新浪合约级日线有一道墙，约 7.5 年** | `RB1905` 有 242 根，`RB1903` 只剩 1 根，`RB1901` 及更早全 null；AG/CU 一致 |
| **①中金所结算价系统性缺失（能力边界，非质量问题）** | IF0/IH0 98.6%、IC0 99.8%、T0 88.1%，**持续到最新一根**。这个源上做不了中金所的逐日盯市 |
| **②按交易所族发生的坏日** | 2021-12-30 三家（SHFE/INE/DCE）、2023-08-28 **两家**（SHFE/INE）、2024-09-25 四家。**INE 必跟 SHFE、GFEX 只在 DCE 坏时坏、CZCE 三次全正常**。原先记的「四个交易所」只对最后那天 |
| **③早期历史缺失** | M0 集中在 2020 上半年、TA0 全在 2014 之前；2020 年起基本可用 |
| **CFFEX 官网 XML 有中金所结算价** | 2026-09-07 那份：714 条里纯期货 28 条，`settlementprice` 与 `presettlementprice` **各 28/28 非零**。探针 `cffex-settlement` 盯着（日期不写死，会随时间前滚） |
| **openmd 目录是 334 MiB，不是 12.5 MB** | `Content-Range` 报 350,177,909 字节。原先的「12.5 MB」是从没拉完的文件上量的，差 27 倍。⚠️ 拉完的耗时**取决于要不要压缩**：端点支持 `Content-Encoding: gzip` ⇒ ~15 MiB / 约 1 小时；不压缩 ⇒ 约 13–20 小时（随线速） |
| **该端点遵守 Range** | `206 Partial Content` + 正确 `Content-Range`。原先记「忽略 Range」是错的，而那个错**恰好让大小的错无法被发现** |
| **截断输入解析【会】报错** | 静默丢合约发生在【修补】上，不在解析器上 |
| **GFEX（si/lc/ps）无夜盘** | 天勤 1m 反推，连续 4 个交易日；对照组 `SHFE.rb` 同法检出 21:00–23:00，证明方法有效 |
| **天勤与新浪的高周期聚合规则完全不同** | 天勤是时钟网格按开盘标注（`09:00 10:00 11:00 13:00 14:00`），新浪是交易时间轴按收盘标注（`09:30 10:45 13:45 14:45 15:00`）；**内容也不同**，不只是标注 |
| **1023 根的日历跨度按品种差近两倍** | 同为 60m：`AG0` 2026-04-13 起、`CU0` 03-04 起、`RB0` 2025-12-22 起 |
| **天勤主连同样未复权，且换月日与新浪不同** | 09-02 换月：主连 +0.61%，两个真实合约均 −1.0% |
| **天勤按交易日标注、新浪按自然日** | 天勤 1m 最早 `01-04 21:00`，其日线最早 `01-05` |
| **gorilla/websocket 连不上天勤行情网关** | 400；开压缩后 101 但报 `invalid compression negotiation`；`coder/websocket` 一次通 |
| 天勤 md 地址必须问名称服务 | `api.shinnytech.com/ns` 返回 `free-openmd`，该域名猜不出来 |
| 夜盘跨日用 `25:00` / `26:30` 表示 | cu 组 21:00–25:00；au/ag/sc 21:00–26:30 |
| 中金所股指与国债时段**互不相同且都异于商品** | IC/IF/IH 09:30–11:30 收 15:00；T/TF/TS 09:30–11:30 收 **15:15**（起点两者相同，差在收盘） |
| 天勤 websocket 的 400 **不是鉴权问题**，是 `permessage-deflate` 协商 | 带合法 token 仍 400；开压缩后 101。**首轮把它读成「缺鉴权」是错的** |
| 快期 OIDC 鉴权路径已确认 | 空密码返回 **422** 且指明 `password` 字段 |
| 四家交易所只有中金所可直连 | CFFEX 200；SHFE 404；DCE / CZCE **412（WAF）** |
| 郑商所 3 位码在新浪返回 **`null` 而非空数组、更不报错** | `TA701` -> `var _=(null)`；`TA2701` -> 154 根 |

### 推定

**外部未文档化，可能在不通知的情况下改变。**

| 推定 | 现状 | 变了会怎样 |
|---|---|---|
| 网格相位 = 「标称夜盘长度 mod 周期」 | 只在 330 分与 240 分两种夜盘上验过。**「沿当天实际时段累计」那一版已被停夜盘日证伪** | `SyncReport.Misaligned` 不为零 |
| 切分规则 = 「从相位起算，沿当天实际时段累计，日末冲刷」 | 4 个周期 × 3 类品种都对上 | 同上 |
| 交易日边界在日盘收盘后、夜盘开盘前 | 由 `AG0`/`CU0` 的网格重启点反推 | 同上 |
| 郑商所 3 位码按「相对该数据所属交易日取最近的将来」展开 | 无官方说明 | 拉到错误年份的合约，或空 |
| 新浪 K 线接口会长期可用 | 目前活跃 | **它的实时接口已经死了两年**，K 线接口没有理由认为一定不会 |

### 未验（**尚不知道，别当成已知**）

**已升级为「实测」、从这张表划掉的**：快期深度分钟历史（890,231 根）、
天勤 `KQ.m@` 的复权口径（**未复权**）、**已到期合约是否仍供分钟线**（供，四个全中）。

| 未验 | 为什么要紧 |
|---|---|
| ~~未完结那一根有没有标志位~~ **已测：结构性不存在** | 字段集里根本没有这一项（不是「值为 false」）。所以判完结**只能靠交易日历**，时间模型那条主线不变 |
| ~~`trading_day_end_id` 是否【预知】~~ **已测：是**（2026-09-07 21:16 夜盘） | 夜盘刚开 17 根而跨度已是整日的 345 ⇒ 预知。探针已转「守基线期」，答案翻转即 FAIL。**但没有证明那个预知值是对的**——见下一行 |
| **停夜盘日 `trading_day_end_id` 是否仍按标称预测** | 跨度 345 = 标称（225 日盘 + 120 夜盘），说明它多半照标称模板算。若停夜盘日仍预测 345，就多预测了 120 分钟，那天**永远等不到 `last_id == end_id`**，「判完结」会在长假前后永远判不出完结。**须在停夜盘日复跑**；验掉之前判完结仍以交易日历为准——⚠️ 而那个退路**本身也有覆盖边界**（见下方静默风险表「把「日历答不了」当成「不是交易日」」那一行）：日历答不了的区间，完结也判不了，`Walk` 会当场报错而不是假装那段没有交易日 |
| `trading_day_length` / `market_time_length` 的单位 | 5190 / 1240 都对不上分钟或秒，含义不明，暂不使用 |
| 实时推送的延迟与断线重连行为 | v1 要接实时 |
| 2016-01-04 是否是**所有品种**的历史地板 | 决定各品种能回测多久。目前只在 `KQ.m@SHFE.rb` 上量过 |
| 新浪与天勤同周期是否逐位一致 | 对不上就必须选一个当真值 |
| `KQ.m@` 与合约的**开盘价**为何偶差 1–4 点 | 收盘价与持仓量逐位相同，唯独开盘价对不上，原因不明 |

### 一类特殊的风险：测试全绿但实现是错的

有些错误**挑错测试参数就永远照不出来**。已知四处：

**一、只测 15m 分辨不出周期对齐规则。**
三个日盘时段（75 / 60 / 90 分钟）都是 15 的整数倍，所以「交易时间轴计数聚合」
与「按时段对齐」在 15m 上**给出完全相同的结果**。一个写错的实现能全绿。
**必须用 30m 或 60m 测。**

**二、只测夜盘长度整除的品种，分辨不出网格是否跨隔夜。**
`CU0` 夜盘 240 分钟，对 30m / 60m 都整除，网格从日盘 09:00 干净地重开。
只拿它测，一个「日盘重新对齐到整点」的错误实现同样全绿。
**必须用 `AG0` / `AU0`（夜盘 330 分钟，对 60m 余 30 分）测。**

**三、只测普通交易日，分辨不出相位是不是按当天实际时段算的。**
平常日子里「按标称模板算相位」与「按当天实际时段算」结果完全相同。
只有**长假前停夜盘**那几天才分得开——那天沪银没有夜盘余数，
按实际算会退化成 `10:00 11:15 …`，而实测仍是 `09:30 10:45 …`。
**必须专门取停夜盘日测**（探针 `grid-phase-constant` 会自己去找）。

**四、把 `null` 归一成 `[]` 之后，就再也测不出代码写错了合约号。**
这一条本仓自己犯过：探针的 `sina_json` 一度把 `var _=(null)` 归一成空列表，
于是「合约号写错」与「这段确实没数据」在解析层之后**就是同一个值**，
下游写什么测试都分不开了。**归一化本身就能消灭一个可测的区分。**

> 这四条的共同形态是：**一个特例恰好让正确实现与错误实现产出相同结果。**
> 选测试数据时，要专门去找能把两者分开的那个参数；
> 写解析层时，要留神别把可分开的两种情况提前合并掉。
> 都写进了 design.md 的测试策略。

### 跨库静默：本库不报错，但下游会得出错结论

| 情形 | 本库做什么 | 下游不看会怎样 |
|---|---|---|
| 同步时有交易日取不到数据 | 列进 `SyncReport.Gaps` | 回测在缺了数据的区间上照跑，产出一个 P&L，没有提示 |
| 换月 | 列进 `Continuous.Rolls` | 把换月当天的基差跳空当成行情收益，且不计换月成本 |
| K 线不完整（停牌/熔断/聚合缺根） | 打 `FlagPartial` | 与完整的那些**长得一模一样** |
| 数据来源不同 | 打 `FlagSrc*` | 两段来源不同的数据接在一起，看不出接缝 |
| 指标未 warmup / 视图无效 | 返回 `NaN` | `if v.Ind("x") > 阈值` 在 NaN 下**恒为 false**，不报错也不触发 |

最后一条值得单说：NaN 是刻意的（0 是个看起来正常的价格），但**与 NaN 比较
永远是 false**。它挡住了「用垃圾值算出一个数」，挡不住「一个分支从此再没进去过」。
循环里用 `View.Ready()` 判，别靠比较。

## 五、版本与兼容性

| | 承诺 |
|---|---|
| **v0.x** | **API 会变。** 时间模型定型前不做任何兼容承诺 |
| **v1.x** | `Store` / `Source` / `Indicator` / `Calendar` 四个接口是对外契约，改它们要换模块路径 |
| **落盘格式** | `.meta` 带 `format`（版本）与 `recordSize`。变更升 `format`，打开时报错并说明怎么迁移。**识别「这是不是我要的那份数据」不靠 `magic`，靠 `Open` 比对全量参数（G1）** |
| **行为变更** | 不改签名但改结果的变更（如换默认复权方式）走 minor 版本并在 README 显著标注 |
| Go 版本 | 1.22，与姊妹项目对齐 |

#### ⚠️ 上面那一行改过三处（2026-09-09），来历写在这儿

**这一行原来是**：「`.meta` 带 `magic` / `version` / `recordSize`。变更升 `version`」。
三个断言挤在同一行，而三个都与 `docs/design.md` §6.1 那份正本对不上：

```
magic       design.md 里命中 0 次；而 .dat 明写「无文件头」
recordSize  design.md 里命中 0 次；记录长 88 只写在【散文】里（:540 / :728 / :1222）
名字        这里叫 version，§6.1 叫 format（JSON 例子 + Go 类型 + 代码都是 format）
```

⇒ 三条判决：

**① 删 `magic`。而理由不是「JSON 结构本身就是 magic」——那条撑不住**：
把 store 指到**另一条序列**的目录，那份 `.meta` 是合法 JSON、有 `format:1`、有 `coverage`
—— **解得出来，magic 也一样（同一个 magic），两者都放行。**

真正的理由是 `design.md` 早就写着的那条承诺：

> `Open` 时会把 `.meta` 里的**全量参数**与请求的参数**比对**，不一致直接报错而不是接着写
> —— **哈希碰撞与手工改目录名都能被挡住。**

**它覆盖 `magic` 想挡的一切，还挡得住 `magic` 挡不住的（同格式、另一条序列）。**
⇒ 删 `magic` 不是放弃识别，是把识别归给一条更强的承诺 —— 而那条承诺此前**没有编号、没有实现**，
所以这一版同时给它编号 **G1**（见 `design.md` §6.1 的不变量表）。**两件事必须同时做，
否则是净损失：拿掉一个弱承诺，而强的那个仍然只是散文。**

**② `version` → `format`，两处**（本行与 `design.md:557`）。§6.1 的 `format` 是正本，不动。

**③ `recordSize` 保留，并且真的进 `.meta`**（新不变量 A4）。而它买到的东西要写准：

> **把「忘了升 `format`」这一件事，在【记录长】这一个维度上，
> 从「靠人记得」变成「当场报错」。它不修那个洞的全部，只修一个维度。**

⚠️ 而不修它的危害是量出来的，比「以防万一」硬得多（详见 `design.md` §6.1 的 A4）：
**记录长减半时，100% 的文件都会被残尾判据误判成「干净」，而每一条记录都还「解得出来」。**

### 已经发生的破坏性变更

按上面 v0.x 那条政策，这些是**允许**的；列在这里是因为
**照着旧版文档写过代码的人需要一份清单**，而不是让他去风险表里翻。

| 变更 | 从 | 到 | 升级时会不会红 | 为什么 |
|---|---|---|---|---|
| `Calendar` 四个方法（`v0.1.0` → `v0.2.0`） | `(X, bool)` | `(X, error)` + 新增 `Covers` | **会红**（签名变了） | 那个 `bool` 承载了两件事：「那天不是交易日」与「日历**答不了**」。内置模板自 2020-05-06 生效而新浪日线自 2009-03-27 起，**中间十一年会被静默跳过**。现在 `ErrNotTradingDay` / `ErrClosed` / `ErrUncovered` 分开，且 **`Walk` 遇到超出 `Covers` 的区间直接报错**——那才是真正拦住它的东西 |

**升级要改什么**：`if !ok { … }` 改成按错误分流。**最省事的
`if err != nil { continue }` 会把三种一起吞掉**，那正是变更前的行为——
所以别只改编译错误，要问一句「这里该不该把『答不了』当成『没有交易』」。

#### ⛔ 而这条变更**只在 `Walk` 上完成了** —— 2026-09-08 实测

`Calendar` 的四个方法，问一个**超出 `Covers`** 的日期：

| 方法 | 返回 | 它把「答不了」说成了 | |
|---|---|---|---|
| `Walk` | `ErrUncovered` | —— | ✅ |
| `DayOf` | `ErrNotTradingDay` | 「那天不交易」 | ⛔ |
| `Template` | **成功，返回一份时段模板** | 「有，给你」 | ⛔⛔ |
| `DayAt` | `ErrClosed` | 「那一刻不在任何交易时段内」 | ⛔ |

> **`Template` 那一格最坏**：前两个至少给的是错误值，**它给的是一个能被拿去算相位的结构体**。
> 而 `Calendar.Template` 的接口文档白纸黑字写着「覆盖不到 → `ErrUncovered`」。

**根因不是「忘了判」，是【问错了人】**：`DayOf` 第一步问 `Template` 「答得了吗」——
顺序是对的，**而 `Template` 的覆盖判据只有品种与 `baseFrom`（2020-05-06），不含注入的交易日区间**；
`Covers` 才是两者的交集。⇒ **一个比 `Covers` 宽的判据，被当成了 `Covers` 用。**

⚠️ **暴露面不是「窄日历」，是任何日历的【未来日期】**（实测 `Covers=[2020-05-06, 2020-05-12]`）：

```
2020-05-13   DayOf ⇒ ErrNotTradingDay   Walk ⇒ ErrUncovered   Template ⇒ 成功
2026-01-01   DayOf ⇒ ErrNotTradingDay   Walk ⇒ ErrUncovered   Template ⇒ 成功
DayAt（用一个【落在时段内】的时间戳，同一时刻 +1 天 / +365 天）⇒ 两次都 ErrClosed
```

**而「明天开不开市」正是 `calendar.go` 亲手点名的场景**：那里写着「本库不猜未来：覆盖不到的
一律 `ErrUncovered`……实盘要判断明天是否开市，得靠交易所公告」。
⇒ **它会回答「明天不交易」，而正确答案是「答不了，去看公告」。**

> ⚠️ **这一格的教训在【记录】上，不在代码上：**
> 上面那一行破坏性变更写着「**现在三种分开了**」——
> 那句话在**类型**上为真（三个哨兵确实存在），在**行为**上只有四分之一为真。
> **一条「已修复」的记录，射程只到它实际改到的那些调用点为止。**
> ⇒ 记一条变更时，要写**它改到了哪几处**，而不是写「这个问题解决了」。

#### 修法本身也是一次破坏性变更 —— 所以它进这张表

| 变更 | 从 | 到 | 升级时会不会红 | 为什么 |
|---|---|---|---|---|
| `Calendar.Template` / `DayOf` / `DayAt` 对**超出 `Covers`** 的日期 | `Template` 成功返回；`DayOf` 报 `ErrNotTradingDay`；`DayAt` 报 `ErrClosed` | 三者一律 `ErrUncovered` | ⛔ **不会红**（签名没变，只有行为变） | 补完 v0.1.0 → v0.2.0 那次变更**没做完的四分之三**。⚠️ **即便它是「修一个 bug」，对调用方而言「原来返回值、现在返回错误」就是破坏性的** —— 一个靠 `Template` 拿模板去算相位的调用方，会从「拿到一份可疑的模板」变成「当场报错」 |

**升级要改什么**：凡是拿 `Template` 的返回值直接用的地方，都要先分流 `ErrUncovered`；
而**原来那条路是静默的**——它不会报错，只会给你一份**属于另一个时间范围**的模板。

> ⚠️ **「升级时会不会红」这一列是后加的，理由值得写下来**（评审方 2026-09-08 提）：
>
> **会红的那些，这张表是【提醒】；不会红的那些，这张表是【唯一的提示】。**
> 两类混在一张表里，读者会用同一种注意力读它们 —— 而后一类需要的注意力多得多：
> 它升级时一声不响，只有行为在某个边界上变了。

⚠️ **而这一版把那次变更补完之后，还剩一处【没补】，写在这里免得下一个人以为全好了**：
包级函数 `embedded.Template(k, num)`（不带 `*Calendar` 接收者的那个）**仍然只判品种与
`baseFrom`** —— 它没有日历实例，**判不了注入区间**。
⇒ 它不属于 `Calendar` 接口契约，所以本次不动；
**但任何直接调它的代码，拿到的仍然是那个更宽的判据。**

现仓库内的直接调用点（`grep` 全仓 `*.go` 排 `_test.go`，2026-09-08）：

```
calendar/embedded/embedded.go  两处   ← *Calendar 的方法，已在自己那一层先判 Covers
tools/probe/shinny/template.go 一处   ← 探针：拿【标称】模板去和交易所实际给的时段比
```

⚠️ **探针那一处是【正当】的，而理由正好说明了为什么包级函数该留着**：
它手上根本没有 `Calendar` 实例，它要问的也不是「这份日历答得了吗」，
而是「**内置表对这一天怎么说**」——**那正是包级函数该回答的问题**。
⇒ 两个判据服务两个问题：**包级答「标称表怎么说」，方法答「这份日历答得了吗」。**
**它们宽窄不同不是缺陷，是分工** —— 上一版的错在于 `*Calendar` 的方法【借用了】前者当后者。
