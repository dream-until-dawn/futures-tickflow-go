# `tools/audit/` — 复现某一条**已记录的测量**的一次性脚本

和 `tools/probe/` 的区别，一句话：

| | `tools/probe/` | `tools/audit/`（本目录） |
|---|---|---|
| 跑的频率 | **每次送审都跑** | 只在复核某条记录时跑 |
| 断言什么 | 「外部世界还是那样」 | 「当初那个数是怎么量出来的」 |
| 耗时 | 秒级 | **从亚秒到几分钟**：`rebuild_docs_test.py` < 1 秒；`gfex_offset_recheck.py` 约 6 分钟 |
| 不跑的后果 | 数据源变了没人知道 | 记录里某个数变成**不可复原** |

**本目录的脚本分三类，退出码的含义按类不同**（2026-09-08 起；上一版写成
「每个脚本的退出码都有意义：0 = 它要确立的那件事仍然成立」，**那句话对第三类是空的**）：

| 类 | 几个 | `0` 的含义 | `1` 的含义 |
|---|---|---|---|
| **检查类** | 6 | 它要确立的那件事**仍然成立** | 不成立，或**这次没验成**（对照组塌了 / 还原不干净） |
| **生成类** | 2 | **产出成功**。它们自己没有 `sys.exit`，但 `rebuild_docs_test.py` 里 `assert code == 0` 在等它们 ⇒ **退出码仍然承重，只是意义在调用方** | 产出失败（异常即非零） |
| **测量类** | 0 | —— | —— |

```
检查类  render_escape_check / section_move_check / sweep_carrier_rules
        rebuild_docs_test（--drill）/ gfex_offset_recheck / gfex_caliber_check
生成类  gen_rule_anchors / gen_quoted_rules
测量类  （空）
```

⚠️ **「测量类」现在是空的，而它此前那一条【归错了】——归类理由要一起改。**

`gfex_caliber_check.py` 被归成测量类时，理由写的是「它没有要确立的那件事」。
**而它有，写在自己 docstring 的第 5 行**：**「差值若正好是边界条目数，解释成立。」**
它的输出也把判据要的**两个操作数都印出来了**（差值、边界条目数）——**缺的只是一行 `if`。**

> ⇒ **一个「docstring 写了判据、输出印了判据的两个操作数、却从不比较它们」的脚本，
> 不是测量类，是【一条缺了最后一行的检查】。**
> 这是「自述比实现【窄】」的一个实例：**docstring 承诺了一个判定，实现少做一步，
> 而输出看起来像一份完整的报告。**

⇒ 2026-09-08 补上那一行，它成了检查类。**「测量类」这一格保留在表里而不是删掉**——
因为「没有命题的脚本不该被逼出一个 `sys.exit`」这条判据本身仍然有效，
**只是本目录目前没有它的实例。**

### ✅ `gfex_caliber_check.py` 曾经是【红的】，2026-09-09 走到复查点，结果是 ①

**复查点就是下面写的那个**（「v0.3 做 Source 那一版」）。走到了，结论是：

> ⛔ **那个红是【这条检查自己】的，不是那个问题的。**

判据原来写的是 `差值 == 窗口边缘不完整条目数`，而这两个量**数的不是同一个总体**：

```
差值   A - B，**只数 GFEX**
边界   edge，数【任何交易所】的不完整条目
```

实测当场就看得见：50% 那一段唯一的边界条目是 `CZCE.PX411P8000`，**一条郑商所的期权**。
它被切断 ⇒ `edge` 记 1；它不是 GFEX ⇒ A 与 B 都不数它 ⇒ 差值是 0。
**0 ≠ 1「判据不成立」——而这什么也没说明。**

> **一条把两个不同总体放在等号两边的判据，会给出一个【看起来像结论】的红。**
> 而它比一条不存在的检查更贵：**不存在的检查不会让人以为有个未解之谜。**

#### ⇒ 判据换成同一个总体之后，两个偏移都成立，而 75% 给出了直接证据

```
50% 偏移 175088954   A 42 ／ B 42 ／ 差 0 ／ 边界含 GFEX 0  ⇒ 成立
                     边界那条是 CZCE.PX411P8000（不是 GFEX）
75% 偏移 262633431   A 86 ／ B 85 ／ 差 1 ／ 边界含 GFEX 1  ⇒ 成立
                     边界那条是 GFEX.lc2606-P-108000 —— **它本身就是一条 GFEX 合约**
退出码 0
```

⇒ **「85 vs 86 是口径造成的」这句话，从「听起来对」变成了【验过】**，
而且验的方式是**把那条被切断的合约的名字印出来**——不是又一个相等的数字。

#### ⚠️ 而这一格上一版记的读数，今天【复现不出来】——那是第二件事

```
上一版这里记 75%：口径 A 86 ／ 口径 B 86 ／ 差 0
今天实测 75%：    口径 A 86 ／ 口径 B 85 ／ 差 1
```

同一个绝对偏移、同一份脚本，隔了时间读出不同的数。原因是文件在长大
（`350,177,909` → `350,338,103` → **`350,757,279`**，比首测大了 566 KB）：

> **一个固定字节偏移，落在一个会长大的文件上，不是一个固定的窗口。**

⇒ 所以「42 vs 38」那个差**从来不是口径问题，是内容漂移**（这一点 `probe.md` 早就写对了）。
新版脚本把它**单独报出来**，不再拿它去判口径 —— **一条检查同时背两个问题，
它红的时候就说不清红的是哪一个。**

**为什么不把它接进送审自检（`CONTRIBUTING.md` 那条命令）**：

```
它走网络 ⇒ 离线、限流、对端变更都会变成红，而那些和它要确立的那件事无关
接进去 ⇒ 立刻得到一个【会红的必过项】，而本仓对那个有专门的一类：
        「一个会红的必过项迟早被加 || true」
```

⚠️ **而「留在手动那一档」有它自己的代价，写在这儿而不是藏着**：

> **一条红着而没人跑的检查，和没有这条检查的区别，只在读者的印象里。**

⇒ **所以它的状态写在这份 README 里**（就是上面那一格），**而不是只写在脚本里**——
**这样「它是红的」这件事，不需要有人去跑它才知道。**

#### ⚠️ 而它需要一个【复查点】，否则它会变成背景

> **一个长期红着的检查，会慢慢变成背景。**
> 它今天是「**一个未解决的问题**」，一年后是「**那个一直红的东西**」。

⇒ **不设期限，设一个【自然复查点】**（评审方 2026-09-08 提，理由是期限靠人记得，
而自然复查点靠工作本身把人带到那儿）：

```
复查点  v0.3 做 Source（新浪 / 天勤）那一版 —— 那一版会重新碰这份数据
结果    二选一，都可以：
        ① 解释了那两个差值 ⇒ 这条检查转绿，或换掉判据
        ② 明确写「仍未解释，且我们决定不再追」⇒ 把这条检查删掉，并说明为什么
禁      第三种：继续红着、没人提
```

> ✅ **2026-09-09 走到了，结果是 ①（换掉判据），见上面那一格。**
>
> ⚠️ 而复查点这个办法**本身也被这次验了一遍**，值得记：
> 触发它的不是「到期了」，是**真的走到那一版去碰这份数据**——
> 写 v0.3 Source 的设计时要引 `probe.md` 的实测结论，顺手跑了一遍全部探针，
> 才看见这一条红。**「靠工作本身把人带到那儿」是成立的。**
>
> ⇒ 而它的**代价**也一起记下：这一格从立到走到，隔了**一天**；
> 要是 v0.3 拖三个月，这条红就在那儿挂三个月。
> **自然复查点解决的是「会不会被想起」，不解决「多久之后」。**

⚠️ **为什么②也算合格的结果**：一个被明确放弃的问题，和一个没人再看的问题，
**在仓库里长得一样，而在读者那里完全不同**——前者告诉他「这条路查过了」，
后者让他以为「这里还有人在盯」。

> **一条退出码没有意义的命令，不能放进任何链子里**——
> 这是「一条被丢弃了输出的命令不能当依据」的镜像。
> 四个脚本曾经只 print 不退非零，评审方在其中一个上抓到，我按同一条把**检查类**过了一遍。
>
> ⚠️ 上一版这里写的是「把**全目录**过了一遍」——**那是假的**：8 个里有 1 个（测量类）
> 从来不在那一类里，**而【它为什么不在】当时没有被写下来**。
> **「全目录」是对我看过的那几个成立的判断，被写成了对目录成立**——
> 和「唯一」同族：**把「我处理过的范围」写成了「存在的范围」。**

**这个目录存在的理由**（2026-09-08 学到的，代价是同一段文档改了三次）：

> 有些格子不是审计漏了，是**它已经无法被审计了**——
> 而记下当时【怎么量的】，本来可以让它可审。

所以：**凡是写进 `docs/probe.md` 的数字，如果它不是一条探针的输出，
产生它的脚本就该落在这里。** 不然下一个人只能「回想」，而回想不是测量。

## 现有脚本

- **`invariant_control.py`** —— 【定点突变】对照组：把实现弄坏，看**预期该失败的那个测试**真的失败没有。
  两组共 14 格：`store/segfile` 片一的 10 条不变量，＋ `Calendar` 契约的 4 条。
  **一个 harness、两组定义 —— 不为第二组新建脚本**（本仓「第二份拷贝」已经栽过三次）。
  它自己复制一份仓库（不带 `.git` / `.env`）在临时目录动手，跑完删。
  ⚠️ **四态判定在这里不是讲究，是必需**：写突变时最容易只想着「怎么违反那条不变量」，
  而**突变体也是代码** —— 三次实测里有三格第一版编译不过，两态的话会被读成「塌了」，
  交出一份假满分。
  ⚠️ 射程：**突变是我挑的，只覆盖我想得到的坏法。**

- **`rebuild_docs_test.py`** —— 重建 `docs_test.go` 里那三张生成的表，**一步到位**。
  带 `--drill`：**演练一次还原路径**（故意写坏 → 还原 → 比对逐字节相同）。
  因为「失败就还原」这条分支平时不会被走到，而**没被执行过的路径与不存在的区别，
  只在读者的印象里**。
  改过五份载体里任何一份，跑它。**它是一个脚本而不是几条命令**，因为原来那条
  用 `;` 串起来的流水线在截断步失败之后照跑，把 `docs_test.go` 写坏过一次。
  每步断言 / 动手前整份备份 / 写完跑 `gofmt` + `vet` / **失败就逐字节还原**。

- **`module_sweep.py`** —— 把**本仓所有 Go 模块**都跑一遍 `gofmt` / `vet` / `test`，
  而不是只跑根模块。**它枚举 `go.mod`，不写死模块清单**，并把找到的清单打印出来
  ——范围写在输出里，而不是写在某个人的记忆里。
  ⚠️ 它的来历：`go test ./...` 够不到 `tools/probe/shinny`（独立模块），
  而那里有两条守卫**从来没有被自检链跑过**。它们当时是绿的，
  **而「它们是绿的」和「它们在跑」是两件事。**

- **`provenance_control.py`** —— `TestHighWaterProvenance` 的对照组，九格，四态判定。
  **它自己复制一份仓库（不带 `.git` / `.env`）在那儿动手，跑完删**，所以跑它不会弄脏工作区。
  其中 **E2 那一格是【期望绿】的**：把当前值和最后一行来历一起改成一致，守卫抓不到——
  那是它的**射程边界**，不是漏网，真正看得见那一步的是读 diff 的人。
  ⚠️ 它进仓库的原因是一次真事：**上一版这个对照组只活在一次性脚本里，
  而其中一行的标签和它实际跑的变异不是一回事**，是评审方独立重跑才发现的。
  **一行标签与实际跑的不符的对照组，比缺这一行更糟**——缺了是一处空白，
  标签错了是一个为错误结论作证的绿。

- **`section_move_check.py`** —— 验「把一条已登记规矩挪到另一个小节底下」会不会被抓到。
  它**应当红**（登记项带所属小节）。自带对照组：真删那一行也必须红。

- **`render_escape_check.py`** —— 量「规矩以**字节不变的方式**失效」那一类还剩多大：
  A2（围栏包成代码块）、A3（行首四空格）各试一次，外加一个对照组（真删那一行必须红）。
  **它跑出来的绿是【已知边界】，不是缺陷**——那一类写在 `docs/method-landing.md` 第三类。
  改了守卫之后跑一遍，确认边界没有悄悄变宽。

- **`sweep_carrier_rules.py`** —— 用一个**和生成器不同的网**扫荡登记表的覆盖面：
  把五份载体里每一行含 `**` 的各删一次（299 行），看守卫响不响。
  **用生成器自己的模式测生成器，得到的一定是满分**——这个脚本存在就是为了绕开那一点。
  它自带对照组（删一份**非载体**文件的三行，必须全绿），因为
  「全都响了」和「这个 harness 永远返回非零」在输出上长得一模一样。

- **`gen_rule_anchors.py` / `gen_quoted_rules.py`** —— 生成 `docs_test.go` 里那三张表（小节锚点 / 逐条登记 / 普查数）。
  **登记表不手敲**：手敲的登记表会在你以为它覆盖住的地方漏掉东西
  （第一版只认 `> **…**` 一种格式，漏了 11 条独立加粗行）。
  改完规矩跑一遍，把输出贴回 `docs_test.go`。

- **`gfex_caliber_check.py`** —— 同一段字节，两种计数口径各数一遍。
  写它是为了验证「差 4 是口径不同」这个解释——**结果两种口径给出同一个数，
  解释不成立**。留着它，是因为下一次再拿「口径不同」当解释时，跑一遍就知道了。

- **`gfex_offset_recheck.py`** —— 复现 `probe.md` §5 那张「按位置采样」的表。
  按**绝对字节偏移**重取（不是按百分比：百分比的分母是文件总长，它会变），
  用来分辨「文件内容变了」还是「窗口挪了」。
  对照组焊在函数里：每个窗口必须①正好 262144 字节②`exchange_id` 计数 > 0，
  否则报「取数失败」而**不报计数**——因为一次失败的取数和「这里真没有 GFEX」
  在输出上长得一模一样。
