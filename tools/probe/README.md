# `tools/probe/` — 探针

**探针不是测试。** 测试断言「本库的行为」，探针断言「**外部世界现在是什么样**」。
所以探针会因为上游变化而失败，那正是它存在的理由；
失败**不代表本库有 bug**，代表 `docs/probe.md` 该更新了。
因此探针**不进 CI 必过项**——一个会红的必过项迟早被人加 `|| true`。

```
tools/probe/probe.py      新浪 / 中金所 / 天勤 openmd（只用标准库）
tools/probe/shinny/       天勤行情网关（Go；服务端要求 permessage-deflate）
tools/audit/              复现某条【已记录的测量】的一次性脚本，见那边的 README
```

## 写一条新探针之前，这八条

都是被真事逼出来的。每条后面括号里是它当初是怎么被撞出来的。

### 1. 必须有对照组，而且**要拆一次看它塌**

一条探针报「没检出 X」时，**「真的没有 X」和「这条探针坏了」长得一模一样**。
所以断言「没有」的探针必须自带一个**已知为真的正例**。

> 焊了对照组 ≠ 对照组在承重。**得拆一次，看它塌。**

（`shinny-gfex-no-night` 里 `SHFE.rb` 那一行防的不是数据变化，是**探针自己失效**。
拆掉它之后拿到过一个 19:12——收盘四小时后——自称「此刻确在盘中」的 PASS。）

### 2. 对照组的价值在它们之间的**差**，不在各自的**值**

**1 个已知值挡不住「恰好返回那个值」；2 个不同的已知值挡得住任何常量。**
`GFEX.si`(09:00) 与 `CFFEX.IF`(09:30) 合起来任何一天都给出**两个不同的已知值**，
「恒返回某常量」的读法当场露馅——**不管那个常量是几点**。

推论：第三个同类品种是**冗余**的；真正缺的是**另一个维度**上的已知值。

### 3. 对照组还要问第三个问题：**它在你最需要它的那一天还在不在**

（`KQ.m@GFEX.si` 做对照组只在**夜盘**成立——GFEX 有日盘，白天跑会走进
「对照组也新鲜 ⇒ 新鲜度判据坏了」分支，SKIP 对但**归因错**。）

### 4. **取不到 ≠ 0；数据不全 ≠ 结论不符**

一次失败的取数会**伪装成一条结论**。所以：

- 找不到就报「取不到」，**别返回 0**；
- 数据看起来不完整时报 **SKIP**，别报 FAIL。

判据要现成、要便宜。例：**首末跨度 vs 根数**——不等就是「数据有缺口」，
不是「模板不符」。（一个量，两处用。）

> ⚠️ **这条最容易只做一半。** 同一次提交里，夜盘那半照做了、日盘那半没做——
> 因为夜盘那半是刚被提醒的。**一条刚学会的规则，默认只作用在学它的那个位置上。**

### 5. 把**判据**和**覆盖面**打进输出

不是为了好看，是因为

**只有把内容摆出来给人看，才有机会发现内容是错的**

。

要打出来的至少有：窗口范围、锚点、你依赖的前提。
（一条探针连错两轮：「我猜了两轮机制都没猜对，**打印出来两秒就看见了**」。
窗口 `[2000 根 08-31 → 09-07]` 一进输出，锚定 bug 当场可见。）

同理：**凡是「照着一个值去操作」的动作——手写期望、手写输入、写变异锚点——
都要让操作对象在输出里露出来**，否则你验证的是另一个东西，而它照样是绿的。

### 6. **依赖「恰好够」的探针 = 迟早会错的探针**

而且它错的时候**不是沉默，是发出一条指控**。

（`view_width=300` 对 rb「恰好够一个完整日盘」——而窗口锚在「现在」，
夜盘从 21:00 起一根根往里挤。那条探针的唯一职责就是指控内置时段表，
于是它在没有依据时发出了那个指控；**照着它改会把一张对的表改错。**）

修法是**显式锚定**（按目标交易日锚，`focus_datetime`），不是加余量。

### 7. **间歇性的错误指控比确定性的更坏**

确定性的错误会被发现、被修；间歇性的指控，自然反应是「再跑一次」——
跑一次就绿了，于是它**永远不会被修，只会被习惯**。
**这就是 `|| true` 的形状，只不过不用谁去加那三个字符，它自己就会变绿。**

⇒ 根因未定时，**先让错误的形态变安全**（止血与修 bug 是两个动作，前者可以先做）。
例：「读两遍必须一致，不一致报 SKIP『数据未收齐』」。

### 8. 探针有**生命周期**：提问期 → 守基线期

判定未验问题的探针，`PASS` 会同时承载「是」与「不是」两个相反结论，
**退出码不再区分**。所以答案一旦拿到，必须把它转成「守基线」
（答案变了就 FAIL），否则**永久丧失发现答案翻转的能力**。

> **转换时机就是拿到定论那一刻。**

做法是加一个 `const baselineAnswer = "..."`，并**变异它一次**确认会 FAIL。

## 还有一条，关于「没有输入能触发这个分支」

写探针时经常要为一个失败补两道防线，而其中一道**通常没有能杀死它的输入**。
三选一，**别默认第三个**：

1. 去找那个能把两道分开的输入；
2. 删掉那道；
3. 留着，但**显式标注**——**连「这段代码从没被执行过」一起说**。

> **「我想不出怎么触发它」是一个缺口；「我找过了，当前触发不了」是一个结论。**
> 前者不该拿来支持「不加」，后者可以——而举证责任在提议的那个人。

## 跑

```bash
python tools/probe/probe.py              # 全部
python tools/probe/probe.py --only sina-frozen
cd tools/probe/shinny && go run .        # 需要仓库根 .env 里的 SHINNY_USER / SHINNY_PASS
```

没有凭证时 shinny 那半打印 SKIP 并以 0 退出——**没有账户的人不该看到一片红。**

### 为什么探针不许 import 本库——**在你想加一条豁免之前先读这段**

`tools/probe/shinny/go.mod` 现在 `require` 本库（带 `replace`），
代价是「探针不 import 本库」从**模块边界强制**降级成了**一条注释**。
`independence_test.go` 顶着它：新探针文件**必须**登记进那张表或写明豁免。

而豁免表就在旁边，**最省事的动作就是加一条豁免**——所以理由必须在这里：

> **探针断言的是「外部世界是什么样」。用本库去解析外部世界，
> 再拿结果验本库，两边会因为同一个原因同时错——那不是两条路，是一条。**

具体到已经发生过的：内置时段表来自 `calendar/embedded`；
如果探针也用 `embedded` 去算「该有哪些时段」，那么**表错了探针不会响**——
而那张表**真的错过**（国债 `dayBond` 写成 09:15，随 `v0.1.0` 发布）。
抓到它的是拿**天勤 1m 实测**去对，不是拿本库对本库。

⇒ 要加豁免，先回答一句：**这个文件拿什么当「外部真值」？**
答不上来就不是豁免，是把探针变成了同义反复。
